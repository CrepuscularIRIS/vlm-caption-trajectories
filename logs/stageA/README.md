# 训练账本诊断：裁图代价在 RLOO 里有多大作用（2026-10-23）

只读 r0（RLOO λ=0）和 r1（RLOO λ=.01）训练时逐条记下的 rollout 账本（每步 12 题 × 16 条，165 步）。CPU 计算，无模型、无新采样。账本含题面，不公开；sha256 前缀：r0 `ea70450b…`，r1 `1d66ab95…`。复算：`python3 ledger_diag.py <账本> <λ> <out.json>`、`python3 push_later.py …`、`python3 -m pytest -q test_pbrs_rloo.py`。

这一项对应导师 10-18 的要求："把 rollout 分成全对、全错、有对有错三组，统计直答和裁图的正确率、advantage、监督 token 数"。

## 结果（r1，按训练步分段）

| 步 | 全对组 | 有对有错组 | 裁图代价项占有对有错组 Σ\|A\|·token | 全对组占全部 Σ\|A\| | 答对样本中：裁 1 次 / 裁 ≥2 次 | 同组内 裁≥2 次 减 裁 1 次的准确率 |
|---|---|---|---|---|---|---|
| 1–10 | .19 | .76 | 2.2% | 0.3% | .50 / .14 | −.07 |
| 11–40 | .24 | .72 | 2.8% | 0.3% | .62 / .22 | −.08 |
| 41–80 | .27 | .66 | 3.1% | 0.2% | .71 / .24 | −.05 |
| 81–120 | .33 | .62 | 4.8% | 0.5% | .65 / .35 | −.01 |
| 121–165 | .33 | .60 | 5.1% | 0.7% | .62 / .38 | −.03 |

1. **λ=.01 太小。** 更新几乎全部来自有对有错组，裁图代价只占其中 2–5%；全对组（代价唯一起主导作用的地方）只占全部信号的 1% 以下。
2. **方向本身是对的。** 同一道题里，多裁的样本本来就更容易错，所以即使 λ=0，一阶上也在推向少裁（`push_later.py`：r0、r1 各段均为负，只有 r0 最后 5 步不显著为正）。问题是力度小，不是方向反。
3. **"少裁"有样本可比。** 约一半的题组里，答对的样本中同时有"裁 1 次"和"裁 ≥2 次"。直答在训练中消失（答对样本中 0 次裁图 .36 → .003），导师说这正常，不影响这里的比较。
4. **单次检查点噪声大。** r1 在 E1 上每题裁图：第 40/80/120/160 步为 1.89 / 1.99 / 3.49 / 2.08。同一 run 相邻检查点能差 1 次以上，所以只看一个检查点比较两个方法，差 0.3–0.5 次可能就是这种波动。
5. **严格势函数在轨迹级 RLOO 下不起作用**（`test_pbrs_rloo.py`，代数检查）：起点势能对同题所有样本相同，留一差里完全抵消；终点势能不为 0 时就等于改了奖励。导师说的势能方程要起作用，要么按轮计算回报，要么接受它改变目标。

导师原公式 r = correct × (1 − λN) 不变，RLOO 不变，只把 λ 提到 .05 和 .10（`lsweep_remote.sh`，10-24 00:49 启动，GPU 0,1 / 2,3），与 λ=0 / .01 构成剂量对照；第 40/80/120/160 步各测 E1 和 E2。
