# Stage 0：用已有分叉检查信号和选路空间（2026-10-23）

来源：Pro / Codex 重设计 [READOUT](../../../docs/archive/research_design/decision_loss_redesign_20261022/READOUT.md) 的第一步。只用已采集的分叉，CPU 计算；没有加载模型，没有新采样，也没有用 GPU。

输入（不公开，因含题面；sha256 记在 `stage0.json` 的 `input_sha256`）：
- 参考模型 r1@40 的 64 个审计状态，每个状态 4 条直答分叉 + 4 条裁图分叉（`audit_states.json`、`score_ref.json`）；
- 首动作监督训练中的 240 个状态（主组，策略在变），每个也是 4+4（`grpo_v3_A_dl_main_forks.jsonl.*`）。

主拆分事先固定为 k∈{0,1} 对 {2,3}，另两种 2+2 拆法作核对。复算：`python3 stage0.py`（需把输入放在 `raw/`）。

## 结果

**1. 收益差 D 主要是信号，不是噪声。**

| | 审计 64 状态 | 训练 240 状态 |
|---|---|---|
| 两半 D 的相关（Pearson，主拆分） | .71 [.53, .83] | .70 [.62, .76] |
| 4+4 估计中信号方差的占比 | 约 .83 | 约 .82 |
| 两半都非零时符号一致 | 40/43 | 133/149 |

三种拆法结果接近（.66–.71）。

**2. D 几乎全由准确率决定，裁图成本只占很小一部分。**

| | 审计 64 状态 | 训练 240 状态 |
|---|---|---|
| 直答分叉准确率 / 裁图分叉准确率 | .09 / .57 | .13 / .58 |
| D 的均值 | −.468 | −.446 |
| 其中准确率部分 / 裁图成本部分 | −.477 / +.008 | −.454 / +.009 |
| D > 0 / D < 0 / D = 0 | 5 / 46 / 13 | 30 / 172 / 38 |
| D > 0 中仅靠省裁图成本 | 1 | 7 |
| D > 0 但直答更不准 | 0 | 0 |

可见收益没有"拿准确率换"的情况；但在 R = Y(1−.01N) 下，省一次裁图只值 0.01，远小于直答丢掉的准确率。

**3. 首动作选路的改善空间很小，参考模型自己的分数已经基本用尽。**（相对"全部裁图"的平均奖励增量，64 个审计状态）

| | 同表（in-sample） | 交叉拟合（一半选、另一半评，两向平均） |
|---|---|---|
| 逐状态完美选路 | .0317 | .0084（用 2 条分叉的 D 决定） |
| 参考模型分数 z 的最佳单阈值 | .0235 | .0197 |
| 完美选路 − 阈值 | .0082（与 Codex 的 .00816 一致） | −.011 [−.038, +.012] |

- 交叉拟合后，用分叉估出的逐状态选路**不比**参考模型分数的单阈值好（点估计更差）。
- 5 个 D > 0 的状态里，有 2 个参考模型本来就几乎必然直答（z > 14）。（勘误 10-23：原写 3 个；第三个 z > 14 的状态 D = 0。Codex 复核发现，见 `docs/research_design/post_crop_decision_20261023/LESSONS.md`。）
- 按 READOUT 的 10% 接管，空间再乘 0.1，同表也只剩约 .0008。

## 解读

- READOUT 的两个停止条件里，"信号被噪声支配"不成立，"收益空间过小"成立。
- 按 READOUT 的规则，第一步结论是**不进入小预测头的分叉采集**（stage 1）。
- 少裁图的空间不在首动作：裁图分叉平均每题裁 1.6–1.8 次，空间更可能在第一次裁图之后的"还要不要再裁"。这是一个新问题，需要单独设计，不在本次范围内。
- 仅为开发诊断：64 个审计状态来自反复使用过的 E1。
- 交叉拟合用的是同一批题的不同续写，不是新题上的泛化；bootstrap 区间固定了拟合出的阈值，没有每次重选。82% 的信号占比是全体状态的估计，不说明 D ≈ 0 附近的状态标签可靠。
