# 决策记录 D：信用分配转向"已有证据的利用"（2026-10-22）

按 Pro 的配对回执诊断方案（[docs/34 第 6 节](34_report_for_mentor_20261022.md)）走到最后一步：一页决策记录。Open Scientist study `rl-objective-credit` 第 014 步，用户批准。

## 1. 各条路线的结论

| 路线 | 结论 | 依据 |
|---|---|---|
| 只看裁图前读者的两格规则（v51_credit） | **停用** | 穷举检查：裁图后的标签从不改变输出（docs/35） |
| 保护"获取到新细节"的动作（Pro 模型三） | **前提没有成立，暂停** | 40 个 SFT-A 状态看图后，"有必要的新细节、且旧轨迹答错"严格 0 个、宽松 1 个，要求 ≥ 8；这是材料不足，不是方法被否定（docs/35） |
| 标准分段优势：用完整续跑的价值，每段拿 V(之后) − V(之前)（Pro 模型一） | **作为参照保留** | 这是标准做法，不改目标 |
| 给"利用已有证据"的步骤分信用 | **转向这里** | 看图观察到的失败主要是选项映射、行列绑定、目标偏移、读错已有证据；文本规则在 RL 后的错题里也大量命中（第 2 节） |

**为什么转向这里：** 如果写出正确事实之后，"继续下去能答对的价值"上升，到作答那一步又掉下来，标准分段优势会给读对的一步正信用、给答错的一步负信用。RLOO 给同一条轨迹的所有 token 同一个优势，读对的一步和答错的一步拿到的信用一样。**更正：** 这个优势的符号取决于同组其他 rollout 的奖励和成本，不是所有错轨迹都为负。

**怎么读这张表：**

   - 失败类型：选项映射、行列绑定、目标偏移、读错已有证据、编造回执，或规则误匹配；
   - 正确事实最早出现在第几轮；
   - 错误从第几轮进入。
2. **分段价值诊断**：确认的病例 ≥ 8 才跑，≤ 2 GPU 小时，不更新参数。在"写事实前、写出正确事实后、作答前"三个边界各续跑 8 次，估计价值；对照组把那句正确事实换成中性占位。
   - 写出事实后价值明显上升，作答时又掉下来 → 分段优势有用武之地；下一步做一组短 RL：分段优势对 RLOO。

   - 区间太宽 → 未决，停止。

## 6. 分段价值诊断结果（10-22，零参数更新）

- **做法：** 13 例（主诊断 9 例 + 混合 4 例），每例用生成这条轨迹的那个策略续跑：SFT 病例用 SFT-A，r1 病例用 r1 第 160 步。
- **四个前缀：**
  - P0：写事实那一轮之前；
  - P1：写完事实那句之后；
  - P1c：把事实换成一句中性的话（对照）；
  - P2：决定性错误之前。
- **续跑：** 每个前缀续跑 16 次，按原协议走到终答。共 832 条，2 张卡约 5 分钟，Open Scientist 第 016–018 步。
- 汇总在 `logs/mve/segval_summary.json`，代码在 `pipeline/eval/mve/segment_value.py`。

### 主诊断 9 例（按病例配对，bootstrap 95% 区间）

| 量 | 值 | 事先写好的标准 |
|---|---|---|
| S3：决定性错误之前的价值 V(P2) | **.53 [.29, .77]** | ≥ .40 且下界 > .20：通过 |
| S2：事实句对中性句，V(P1) − V(P1c) | **−.13 [−.44, +.11]** | > 0 且区间不含 0：**不通过** |
| S1：事实句对写之前，V(P1) − V(P0) | −.08 [−.25, +.08] | 只作描述 |
| 写之前的价值 V(P0) | .66 | 只作描述 |

**判定（独立审查）：** 按事先规则，**竞争解释成立**：在这些切点上，事实句没有测出高于中性句的价值增量。这**不**说明读取没有价值，也**不**说明能力有上限。

### 数据显示的情况（描述性，不改变判定）

1. **价值已经饱和。** 写事实之前，V(P0) 平均就有 .66，9 例里 4 例 ≥ .875。事实句几乎没有上升的空间。
2. **错误分两种。**
   - u04、u38、u39：错误之前 V(P2) ≥ .9，同一个状态下策略几乎总能答对。这是**偶然失误**，符合 Pro 决策表的"先当作采样噪声"。
   - u06、u11、u17、u37：V(P2) ≤ .25，策略多半会重复同样的错误。
   - u01、u28 介于两者之间。
3. **对照句不中性。** 中性句在 9 例里有 7 例紧跟在 commit 标题后面，8 例里续跑都裁得更多、写得更长。S2 为负来自两个 r1 病例（u37、u39）；SFT 病例 S2 平均 +.125，r1 病例平均 −.45。
4. **切点非常敏感。** 有 5 例的 P2 和 P1 只差末尾一个空格，结果 u39 从 2/16 变成 16/16。按字符切的前缀会改变 token 化，这个测量本身还不稳定。
5. **混合 4 例里有 3 例，错误出现在事实之前。**

### 对下一步意味着什么

- **按 Pro 的决策表：** 测量的前提（按句子切出的前缀价值）还不可靠，**应先修测量**：切点要对齐到真实的 token 边界，对照句要真正中性，也就是不改变动作结构和长度。在这之前，不启动"分段优势对 RLOO"的 RL 对照。
- **"偶然失误"这类病例值得留意。** 如果大量错误来自"同一个状态下多数时候能答对"的失误，那么信用分配的重点应该是"别把读对的部分一起罚掉"，而不是"教模型学会用证据"。这仍是假设，需要在修好测量之后，用更多候选来检验。
