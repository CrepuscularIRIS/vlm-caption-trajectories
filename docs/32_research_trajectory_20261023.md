本文把导师 10-16 回复之后的全部步骤按时间串起来，写清每一步：

- 为什么做；
- 怎么做；
- 结果如何；
- 学到了什么。

**网页 ChatGPT Pro 的四轮诊断与设计**（10-22、10-23 上午、下午、晚上）在第 4 节单独展开；Pro 的全部推断及其证据状态汇总在第 4.6 节。各步细节以所引文档为准，本文不新增实验结论。

## 0. 一句话

- **目标没变**：准确率不降、保住恢复能力，同时减少**第一次之后的无效裁图**。
- **到目前为止，没有一个方法达到这个目标。** 十余组 RL 训练和 1 个首动作监督 MVE，要么塌缩，要么准确率掉，要么裁图不少反多（第 1 节）。
- **但研究方式已经回到正轨。**
  - 问题已经收窄：从"整体少裁"收窄到"第一次裁图回执之后，能不能停"；逐图审查后进一步发现，"多余裁图"里混着四种不同的失败（拿不到、找错地方、拿到了没用对、本可以停），下一步先查"证据 → 事实 → 答案"在哪里断了（第 4.5 节）。49 轮直接审查进一步分出三类：看错后继续找、知道缺什么但动作无效、已判断正确却继续确认。
  - 研究顺序已经定下：先证明有空间、能识别，再决定给谁什么损失。
  - 否定一个设计的成本大幅下降：10-21/22 的一次否定要约 30 GPU 小时训练；10-23 的 Stage 0 用已有分叉、约 1 小时 CPU 计算，就挡下了一个空间太小的方案。
- **正在进行**：从这个领域的前人工作中，系统提取**信用分配与 advantage 的问题**、前人的思维方式和创新模式。语料与 card 在一个私有仓库（`vlm-caption-corpus`）里审阅，较慢，完成后再出卡片、和导师一起分析（第 6 节）。

## 2. 10-16 → 10-20：奖励与优势层面的尝试

**2.1 裁图代价一加就塌缩（docs/23）。** 一组 16 个采样全答对时，GRPO 优势 = −(k − 平均 k) / std(k)，λ 被约掉。"少裁一次"的推力和"答对 vs 答错"一样强，经共享参数扩散到需要裁图的题上。文献中有同样报告（Arora & Zanette 2502.04463 §5.4.1；Dr. GRPO 2503.20783）。

**2.2 修了尺度，没修效率。**
- std 下限、卡 A/B、KL 都不塌缩，准确率都在 .647–.666 之间，差异在噪声内。
- 只有卡 B 和 std 下限明显少裁。
- 结论（docs/28）：只改奖励或优势，只能在"多裁 / 少裁"之间移动。

**2.3 GAP（docs/28）。**
- RL 后几乎每题都裁（locate .999）。
- abstain 0%，REVISE 0.1%：模型从不表达"不确定所以再看"。
- 答案式基线证明：SFT 里没有的行为，RL 学不出来。

**2.4 两分支 + dV（docs/29）。**
- 两分支测量本身有效。
- dV 只是叠加在结果优势上，抵消不了混合组里"裁图平均更准"带来的负优势。首轮裁图比例两组都到 1.0。
- 多出来的裁图集中在后续轮次。**这是"后续冗余"第一次被明确看到。**

## 3. 10-21 → 10-22：RLOO 对照与四种情况信用

**3.1 导师的两条建议。** 一是先查 advantage（RLOO λ0 vs .01）；二是按"裁图前 → 后"的对错分四种情况（错 → 对、对 → 对、错 → 错、对 → 错）分配信用。

**3.2 RLOO 结论（docs/30 §2）。** 塌缩来自除以 std，RLOO 不塌缩。但 RLOO λ.01 和 λ0 的裁图几乎一样：**advantage 的形式解释了塌缩，没有解释效率。**

**3.3 训练前的四个诊断（docs/30 §3–4）。**
1. 冻结读者判出"对 → 对"占 47%。但读者不是策略本身，不能证明这次裁图多余。
2. 我们手写的四格规则只看裁图前的对错，**导师的四种情况其实没被实现过**。
3. 决策点基线的门槛没过（这不等于方法失败）。
4. 挖病例时测到的是"读对数字、选错选项"，属于答案映射错误。**它和裁图效率是两个问题**，我们当时把两者都叫成"信用分配"。

**3.4 fc 与 zero（docs/30 §7.1–7.2）。**
- fc 裁图反而多了：裁图轮新信号平均 +0.03 ~ +0.06，原 RLOO 优势是 −0.01 ~ −0.02，裁图变得更划算。
- zero 少裁了，但掉准确率。
- fc − zero 的准确率差为正，按预注册判"前后信息有作用"。但这是因为 zero 掉了分，fc 本身不比 r1 好。

## 4. Pro 的四轮诊断与设计

每一轮的流程相同：

1. Codex 写设计任务，并附上导师原话、结果、代码和卡库；
2. 网页 Pro 读取公开仓库的固定提交，独立诊断，再给设计；
3. Codex 用 CPU 复算关键数字。

Pro 的输出一律当作待核验的建议，不直接当结论。

### 4.1 第 1 轮（10-22）：把导师的"直接监督动作选择"落成可执行的 MVE

**诊断**

- **协议里动作被 WORD 提前承诺。** `Step N | WORD` 中，locate / re_examine / fallback 必须接 grounding，commit / abstain 必须接 answer，违者判 invalid。
  - 所以在"同一个 caption 之后"分叉出两种动作，其中一支必然格式非法。测到的差异首先是格式差异，不是任务价值。
  - 最小修订：只放松第 1 步的 WORD 语义（v5.2i），后续轮次不变；正常 rollout、分叉、训练、评测都用同一版本。
- **fc 不是势能塑形。** 势能塑形保最优策略不变，需要三个条件：把 F = Φ(s′) − Φ(s) 加进整条 reward-to-go；Φ 是真正的状态价值；终止边界处理正确。
  - fc 三条都不满足：它是替换裁图轮优势；Φ 用的是"现在就答"的成功率；失败的裁图也扣 λ。
  - 在一次裁图的简单情形下，fc 比导师的路线收益差多出一项 −λ(1 − q_c)。
- **同一份分叉信息有四种用法**（当奖励、当优势、当信用路由、当辅助损失），目标与梯度落点都不同，不能混着比较。
- **K = 4 的估计不只是加零均值噪声。** 取正负号和绝对值之后，BCE 的期望监督会变形。Pro 给出了两个精确反例。

**设计**：RLOO 加"首次动作收益差 BCE"。β 固定，同一次优化步更新；β = 0 作唯一对照；按共同参考状态测 U_choice。

**结果（10-23）**：否定。直答整体变多，没有按状态区分。

### 4.2 第 2 轮（10-23 上午）：失败后的重设计

**诊断**

- **三次失败的方式不同。** fc 没少裁；zero 少裁但掉准确率；DL 少裁但准确率 CI 很宽。不能说成"都没少裁"（我们的报告原来就是这么写的，已改）。
- **"BCE 在 p ≈ 0 处饱和"不是已查明的原因。** 已选对的状态梯度小是正常的。要解释的是：别的状态的更新，为什么把这些本来选对的状态也带向直答？
  - 可能的原因有共享参数干扰、RLOO 与辅助项的叠加、优化器、K = 4 噪声，现有证据分不清。
- **不是一个统一偏置。** 64/64 个状态的直答概率都上升（我们原写 61/64，已改），状态排序也变了。
- **生产接线没查出常见错误**，比如符号写反或 mask 错位。

**设计**

- 冻结 r1@40，只训练一个小线性头，预测有符号收益差 D = Q_answer − Q_crop；只在预定的 10% 轨迹上接管首个动作。
- 唯一对照：用同一批分叉，校准原模型动作分数的最佳单阈值。
- 要回答的问题：隐藏状态里新增的信息，能否比原分数的一维校准更好地判断何时该停？

**第一步是零 GPU 检查（Stage 0）。**

**Stage 0 结果（CC 执行，logs/dl/stage0）**

- D 两半的相关约 .70，信号占方差约 82%：D 不是噪声。
- D 几乎全由准确率决定：直答准确率 .09，先裁准确率 .57；裁图成本只占 +0.008。
- 同表完美选路比最佳阈值只多 .0082；交叉拟合后为 −.011 [−.038, +.012]。
- 按 READOUT 的停止规则，**不进入 stage 1**。
- Codex 复核时指出两处需要收紧：
  - 一个计数应为 2 而不是 3；
  - 交叉拟合是同一批题、不同续写，不是新题上的泛化。

### 4.3 第 3 轮（10-23 下午）：转向"第一次裁图之后何时可以停"

**诊断**

- **用人话讲导师的建模顺序。** 先找一个具体时刻，问模型此时能看到什么、能合法做什么；再比较两条可执行的后续路线；只有存在值得学的差别，才决定把信号给谁、用什么损失。**先定行为与测量，再定公式。**
- **四个层次继续分开。** 任务目标 / reward、advantage / baseline、信用路由、动作监督，各自不能证明什么，见第 3 轮回复 §1.1。
- **"只在裁图动作上改信号"的问题需要说准确。** 动作相关的 advantage 本身完全合法，问题在于把未补偿的动作相关项冒称为零期望 baseline。
- **暂不转向势能 shaping。** 只有所有终止类型（包括 invalid、长度和预算终止）都有合适的终端势能，整条 return 也按同一规则处理，才得到动作无关的边界项。何况现在还没有可靠的后裁价值测量。

**设计（主卡）**：首裁回执后的停止 / 继续价值，分三层依次证明。

1. **有空间**：现在停比继续省，答题和必要的恢复不受损；原模型还没有利用这个机会。
2. **能识别**：只凭当时可见的信息，就能区分该停和该继续，而且比原分数的阈值更好。
3. **能学会**：把信号写回原模型后，自然生成真的改善。

测量位置在首裁回执进入上下文之后、下一轮任何 token 之前，比较三条路线：

- S：在 commit / abstain 两个合法 WORD 内采样，然后作答；
- C：在 locate / re_examine / fallback 内采样，再取证，然后自然完成；
- 自然参照：原模型不加强制的后续。

同时看 D = Q_S − Q_C 和 T = Q_S − V_nat。

**候选损失（未放行训练）**：对原模型五种 WORD 的分布按收益差做有限倾斜，带 KL 约束。单状态时的解析解为 p* = σ(logit p₀ + D/τ)。三项风险未解决：

- 极端概率处梯度仍小；
- 共享参数会牵动 caption 和答案；
- 五条路径的总概率可以同时下降，而归一化 KL 不变。

**下一步**：零 GPU 的状态清单与协议核查，即首裁后的 token、图像回执、协议版本和剩余预算能否精确重建。之后才考虑小额分叉 Probe：最多 64 题组、128 条后续、硬帽 2 GPU 小时，尚未授权。

**尚未定下的部分**

- recover 的"不确定性"怎么定义和测量；
- "足够空间"和"明显伤害"的效应阈值；
- 封存测试集：E1 已被反复使用。

### 4.4 CC 的轨迹阅读（docs/31）

我们读了 r1 第 160 步的 2,208 条轨迹（clean / E2）。主要发现：

- 4% 打满 7 次上限的轨迹，贡献了 24% 的后续裁图。这些轨迹是**在几个区域之间来回切换、证据始终没整合**，不是反复确认。
- "确认后马上作答"约占后续裁图的 9%，这是真正需要权衡的部分。
- 原地重复或裁整张图约占 8%，最接近"没有新信息"。
- 首裁偏移后，模型 77% 改为 fallback，准确率几乎不掉（.663 → .653）：**后续裁图里有一大块是恢复**。

建议给第 3 轮的分叉 Probe 按这些可见类型预先分层抽状态，并事先写下预测。

### 4.5 第 4 轮（10-23 晚）：逐图审查后，"多余裁图"拆成四种失败

**起因。** 第 3 轮的主卡假设"后续裁图中有该停没停的"。Codex 先在 CPU 上重建了 10 条轨迹（8 个题目）的 49 个视图位置，按学生实际收到的回执逐张看图（37 张不同图像），再把图和标注交给 Pro。这些是挑出来的反例和候选，**不是全库占比，也不是人工金标**。逐图证据见 [CASES](research_design/trajectory_root_audit_20261023/CASES.md)。

**Pro 核图后的判断（逐病例）**

|---|---|---|---|

| c06 | 嵌套裁图放大了人物和骑车者的身份细节 | 不能按"嵌套"一律处罚 | — |
| c07 气球 | 首裁已能看出红气球低于白气球，仍继续放大 | **最像"本可以停"的候选** | 还没证明学生此时直接答也能答对 |
| c02 / c03 | 静态图不能直接测车速，但题目是行为预测 | 没有完整题面，不宣布不可回答 | — |

**四个环节不能强行互斥分类，一条轨迹里可以先后出现：**

| 环节 | 本轮支持的观察 | 尚未识别的关系 |
|---|---|---|
| 可获取性 | 通知栏无法通过裁图变成主屏幕 | 现有答题指标下这类题该怎么处理 |
| 定位 / 呈现 | 财务图回执长期落在非目标区域 | 改框、改尺度、缩短历史各贡献多少 |
| 读取 / 绑定 | c01 可辨数值与写出的数值不同 | 视觉读取、语言锚定、随机生成、答案承诺各占多少 |
| 停止 | c04 / c07 存在看清后仍继续放大的状态 | 同状态立即作答能否保持准确率 |

**Pro 对导师思路的再解释。** 从终局 RLOO 到"同状态比较动作价值"，是把"整条轨迹好不好"细化成"此刻选哪个动作更好"。逐图证据要求再往下问一步：**错误真的发生在动作选择上，还是动作所依赖的事实已经错了？**

**目标、估计器和信号落点要分开（Pro 第 4 轮 §3.1）**

| 改动 | 直接改变什么 | 要避免的误读 |
|---|---|---|
| 状态 baseline / advantage | 给定目标下的梯度估计与方差 | 方差下降不等于教会了更好的停止边界 |
| 加事实、长度或一致性 reward | 优化目标本身 | 不能称为原目标下的"无偏信用修复" |
| 只把信号给部分 token | 参数更新的路径和权重 | token mask 不等于因果贡献，也不会冻结其他行为 |
| 动作 BCE | 状态条件下的动作偏好 | 只有比较对象和前缀合法，标签才有含义 |
| 局部事实监督 | 从当前上下文生成正确事实 | 不保证事实影响答案，更不保证少裁 |

"改变目标就是错"不是合理限制，但目标改变必须明说；"期望梯度不变"也不是本研究必须追求的结果。

**历史成本不能随便删（§3.2）。** 当前奖励 R = Y(1 − λN)，没有其他过程奖励。设已用 n 次裁图，S = 现在答，C = 继续并自然完成（之后再用 M 次）：

$$
D=Q_S-Q_C=(1-\lambda n)(p_S-p_C)+\lambda\,\mathbb E[Y_C M].
$$

- 成功率相同时，停止省下的是成功轨迹的成本；
- 继续能提高成功率时，多出的成本可能值得；
- 两次观测都答错，不等于两条路线的真实成功率都是 0；
- 若两条路线成功率真的都是 0，原奖励无法只凭裁图数区分它们。所以**不能统一处罚"必要但这次失败的探索"**；想在必然失败时也学会省成本，就得显式改目标。

**协议决定了每类问题的干预位置（§3.3）。** 训练实际走 `v51_cropfloor → caption_v51 → caption_v3.check_step`，**每一轮**都绑定 WORD 与动作（v5.2i 的首轮豁免只在首动作监督实验里）。所以：

- 选"停还是继续"：共同前缀必须在下一轮 WORD 之前；
- 选"去哪里裁"：在已合法选择 grounding 之后比较 source / bbox，这是定位问题；
- 查"读出的事实怎样影响答案"：固定合法的 commit 轮，在事实或答案承诺之前做局部检查，这是证据使用问题。
- **WORD 在 caption 之前生成**，修正本轮 caption 改不了本轮已选的 WORD。训练事实 token 只能经共享参数间接影响以后的 WORD，这要实测。

**设计：一张主卡。** "已到达证据的读出—使用断点检查"，匹配 K25（在模型自己的 trace 上做 probe）、K24（独立视觉事实核验）、K46（协议差异诊断），思路来自 diagnose_then_target / C02。核心区分：**事实正确、事实被利用、工具有价值，是三个不同的判断。**

**最小 Probe（零生成、零更新）。** 以 c01 做仪器验收：保持之前全部历史和视图不变，在合法的最终 commit 轮比较三种写法。

| 条件 | 写出的数值 | "对应 A"这句承诺 | 作用 |
|---|---|---|---|
| O 原貌 | $1.32M | 保留 | 参考 |
| B 匹配对照 | $1.32M | 删除 | 控制"删掉承诺"本身的影响 |
| F 事实修正 | $1.38M | 删除 | 只和 B 比，看数值修正的作用 |

- 只算每个完整合法答案序列的条件 log-prob 之和；主要看正确选项相对最强错误选项的 margin，以及 F − B。强制写入的事实本身的似然不计入。
- 解读：F 比 B 好 → 正确的文字事实有助于选对，但不证明学生能自己读出；删掉承诺 B 就变好 → 先考虑答案承诺 / 锚定；B、F 都对或都错 → 保留采样、绑定、上下文等解释，不判"能力不足"。
- 预算：Pro 的通用上限是 32 个固定后缀评分、100 万输入 token、0.5 GPU 小时。本例 5 个选项，实际 15 个答案评分，加可选 2 个事实评分，至多 17 个。**尚未运行。**

**条件性训练建议（未放行）。** 只有确认事实读取断点能被自主改善、并且和任务成本有联系之后，才考虑 RLOO 加"核验过的事实 span 交叉熵"。这明确改变训练目标，是辅助监督，不是原奖励下的无偏 advantage。必须同时有普通答案监督作简单对照，并保留原 RLOO 参照。若实际只是答案绑定问题，就不训练读图 span；若目标区域从未拿到，事实监督替代不了定位。

**Codex 复核补充的边界**

1. c01 原题选项已在服务器原 parquet 上核实：A = $1.36M、B = $1.38M、GT = B（只读题面与选项，未复原生产输入张量）。
2. F − B 只识别这个构造上下文里的文本数值响应。$1.38M 恰好匹配 B，所以阳性也可能只是普通的文本选项匹配，不能证明视觉使用。
3. **末轮错读不是此前多裁的原因证据。** 只有在还有后续搜索的中间状态反复看到同类断点，并验证它影响后续行为，才能把它当成效率研究的主线；否则它是答案链条上的局部诊断，要和停止价值问题分开。
4. 还不是可执行的 PREREG：要锁定 r1@160 权重、原始与重建输入的口径、候选结束符、温度处理和评分实现。r1@160 的证据不能替代 r1@40 或 SFT-A 的状态测量。
5. E1 不再用来证明泛化；确认性比较需要独立的题目 / 图像家族。

**文献边界。** Codex 核对了 K25 / K24 / K46 全文，以及 ACRE（2510.10104 §3.2–4：固定媒体与 trace，改选项顺序查一致性）和 VAPO（2509.25848 §4.2：在推理前缀插入视觉 claim）。所以**"在自己的 trace 上加一个事实 probe"本身不是创新**。本轮交付是一张可否证的诊断卡，不是方法贡献。


**Codex 直接看图的深化审查（10-23 晚，Pro 第 4 轮之后，未再咨询 Pro）。** 同一批 10 条轨迹，逐轮核对全部 49 轮：当时可见哪些图、模型说了什么、随后实际裁了哪里。完整题面从数据文件核回。见 [direct_review](research_design/trajectory_root_audit_20261023/direct_review/README.md) 与 [49 轮逐步标注](research_design/trajectory_root_audit_20261023/direct_review/TIMELINE.md)。

**结论：至少要分开三类，**它们需要的干预不同：

1. **看错后继续找**（c01 中间状态、e08）：错在状态描述和下一框去哪，只监督"答 / 裁"标签修不好；
2. **知道缺什么，但动作无效**（c00、c03）：工具够不到，问题在"识别信息不可得"；
3. **已判断正确却继续确认**（c04）：最贴近导师的 stop / crop 公式，需要同状态比较停与继续。

另有一条与效率无关、但与信用分配直接相关的发现：**c02 这种"字母对、理由错"的轨迹会拿到满分结果奖励。**

**它修正了我们之前的判断。**
- docs/31 把封顶循环归为"证据没整合"。c00 说明其中一部分是**工具本身拿不到信息**。
- docs/31 把"确认后作答"算作待权衡的一类。c05 说明"确认"也可能是在补齐证据，不能作冗余标签。

1. **领域内的信用分配与 advantage 问题**：前人遇到过哪些问题、怎么诊断、怎么修，比如 std 归一的偏置、动作相关基线、按 token 平均与长度不对称、工具调用塌缩、按收益决定工具奖励正负等，并写成工程经验。Codex 第一版见 [LESSONS](research_design/post_crop_decision_20261023/LESSONS.md)。
2. **前人的思维方式**：严格按 ResearchStudio 的领域 + 跨领域框架，整理每类工作是怎样提出问题、怎样设计对照的。
3. **创新模式**：一类问题在前人那里是怎样推进到新方法的。

语料和 card 在私有仓库 `vlm-caption-corpus` 中审阅，速度较慢。完成后：出卡片 → 和导师一起分析 → 再定后裁停止的测量与方法。

## 7. 后续问题清单

**请导师确认的**

1. **目标的口径。**
   - 是要一个"成本-准确率权衡点"？这时要改 λ，或者给裁图预算。
   - 还是要"去掉无用动作"？这时要能识别它。
   - 当前 R = Y(1 − .01N) 下，一次裁图只值 0.01，只要裁图对准确率略有帮助，RL 就不会少裁。
2. **哪些后续裁图算冗余。** 原地重复或裁整图、确认后作答、封顶循环，三类是否都算？封顶循环是能力问题（整合不了证据），是否在本课题范围内？
3. **"工具拿不到信息"的题怎么算。** 例如通知栏挡住主屏幕：裁图无法获取信息。这类题是排除、单独报告，还是期望模型识别后作答 / 拒答？后者会改变目标。
4. **recover 的定义。** "下一步推理存在不确定性时才补看"，用什么测当时的不确定性？错框条件下的成功率只算压力测试。
5. **评测。** E1 已反复用于开发，需要封存测试集；导师要求的 HR-Bench / TreeBench / O3Bench / VisualProbe 仍不在服务器上。
6. **协议。** 每一轮的 WORD 都绑定动作。分叉要么选合法的共同前缀，要么把协议修改作为显式变量，哪种可以接受？

**我们自己要回答的**

7. **advantage 与信用路由。**
   - 动作相关项什么时候合法，什么时候在冒充 baseline？
   - 按 token 平均时，长轨迹（裁图多）承载更多梯度，影响多大？
   - 辅助损失经共享参数牵动 caption 和答案，影响多大？
8. **势能塑形的前提**能否在本协议里满足，尤其是 invalid、长度和预算终止的处理。
9. **证据 → 事实 → 答案在哪里断了**：c01 的错误在第 3 步就出现（认错对象），之后的裁图理由都沿用了它。要研究多裁，应查中间状态；末轮的 17 个评分检查只说明末轮答案使用。
10. **后裁停止空间有多大**：零 GPU 状态清单，再按可见类型分层做小额分叉。c04 这类"已写出正确关系仍继续"的状态是首选候选，c05 / c06 作不应误伤的对照。
11. **"字母对、理由错"怎么算**：c02 这类轨迹拿满分结果奖励。要不要（以及怎样）检查答案与解释一致？这会改变目标，需要导师决定。
12. **种子**：所有结论都是单种子。同一配方两次运行的 E1 差 1.6 个点（.664 vs .648）。
