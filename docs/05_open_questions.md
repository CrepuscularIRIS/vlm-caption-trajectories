# 当前问题与需要讨论的取舍

## 1. 行为覆盖仍未完成

**观察**：16 条 clean 轨迹中 HOLD 1、REVISE 0、fallback 0。补覆盖生成 12 条，8 条实际裁图，仍没有 HOLD/REVISE。

**可能解释**：题目缺少真正的保持/修正机会；提示与生成档位不适合表达更新；模型发生无声改值；合格行为存在但最终答案或风格门未过。现有小批不能排除这些解释。

**建议**：下一次补覆盖先写清每题的“行为机会”，再看是否发生、是否通过复核；不只按高分辨率或困难题标签挑题。分别报告机会题数、实际事件数、合格轨迹数。当前尚未运行新批次。

## 2. 示范构造可以允许多少引导

待讨论的选择包括无 gold、无目标坐标的通用教师指令或少量真实示范，帮助表达“暂定候选 → 核验 → 保持/修正”。这是训练数据构造，不要求教师完全不受指导。

边界是不能预写哪一步必须错、不能人工伪造失败 crop、不能编工具返回或拼接教师路径。若从真实失败前缀继续执行，保留分支和反馈来源；确定性错误前缀进入恢复用途，不能全段当 clean 正例。

## 3. 单次盲读不能当真值

1746 在重复读取中出现不同裁决。1789 的关键事实审查漏掉部分 HOLD 绑定问题。增加评委数量不自动解决相关错误。

当前建议继续小批关键行为的人工看图，保留 INSUFFICIENT 与争议状态。若要升级审计，先针对实际漏检做最小验证，不循环调用到出现期望结果。

## 4. 选择流程仍有召回边界

首个自动候选通过后审计停止。若它被人工否决，当前不会自动复查该题其他候选。终答读图最多保留 3 个引用视图；关键事实抽取仅 1–3 条；schema 验证也不是完整更新事件检查。

这些是实现限制，不应宣传为完备的自动验收。应在相关样例出现时评估最小修复价值，而不是为了公开展示先搭一套更复杂系统。

## 5. 训练衔接还有缺项

16/16 CPU 检查仅覆盖现有类型。尚无合格 REVISE/fallback、恢复池与后缀监督验证。教师与学生像素可读性差异也没有由这些计数解决。

当前可交付“种子轨迹与构造管线”；是否做训练、做何种最小对照，应另行确定。模型演示、数据可加载与学生学会之间不能互相替代。

## 6. 成本与工程稳定性

已有执行记录指出 GLM 在冒烟中出现 1 次 api_error、2 次截断，隐藏推理 token 成本较高。当前没有在公开包中重算完整供应商账单，因此不发布精确单条货币成本。

调用成本应包含拒收、重试与审计，分母用最终交付轨迹数；不要只报成功请求的均值。公开元数据保留生成请求计数与终态，后续可据完整私有账单核算。

## 建议的讨论顺序

1. 这 5 个真实正反案例是否符合要教给学生的行为？短证据与绑定信息是否足够？
2. 接受哪些生成期通用引导？如何区分 clean 示范、脚手架蒸馏与错误前缀恢复？
3. 是否先接收 16 条种子子集，并按明确机会小规模补齐行为？
4. 新题源怎样提供缺失机会，而不只是增加难度或题量？

建议倾向“先交付种子子集，难题源作为储备”。这不意味着放宽原行为门，也不意味着只等待 MMMU-Pro/MME-RW 完整版即可解决问题。现阶段不再为过门原样追加自然抽样；保持已预登记的停止规则。
