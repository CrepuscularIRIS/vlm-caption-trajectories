## 2. 逐条整理

**判断：**

| 导师说的 | 含义 |
|---|---|
| 整体结果正向；原始 A 已能教会有用行为，并支持后续 RL 提升 | 主线定为 A |
| GRPO 把主动观测搞得有点过头 | 对应报告第 8 节：直答 43% → 0.1%，原本直答对的题掉分 |
| B 让模型回到原目标，但收益不多；插值不必再扩大，也没有干扰梯度 | 不再扩大插值库；B′（只差一个变量的对照）不做 |

**要求：**

1. 从 A 的 SFT checkpoint 重跑 GRPO。
2. 先检查直答：模型看原图后直接作答，能否正常终止、正常打分。
3. 奖励里不给 hit / fallback 这类字面标签加分。
4. 不因为没调用工具而扣格式分。
5. 另跑一组带裁图约束的奖励：`reward = correct * (1.0 - 0.01 * crop_count)`。
6. 用同一个验证集，和原版 GRPO 对比。
7. 目标：减少无效裁图，同时保住答题和纠偏（recover）能力。

## 3. 现有代码对照（2026-10-16 只读核对）

在服务器上核对了上一轮 A、B 两组 GRPO 实际用的代码，两组的奖励文件相同。

| 要求 | 现状 |
|---|---|
| 3 不给字面标签加分 | 已满足。奖励只看终答：唯一一个 `<answer>` 且字母等于正确答案得 1，其余 0。没有格式分、标签分、裁图分、过程分。 |
| 4 不因没调用工具扣分 | 已满足。第一轮直接给出答案即可结束，不要求先裁图。 |
| 2 直答能否终止、打分 | 代码路径上可以：第一轮解析为答案就记为正常结束，进入打分。协议检查里没有“必须先裁图”的规则（fallback 才要求之前裁过图）。**还没在训练日志里实际核对**：需确认 GRPO 早期的直答样本确实拿到了 1 分，而不是被判成无效。 |

所以“直答消失”目前看不是奖励或格式检查的错，更可能是只奖励对错时，多裁一次几乎没有代价、又可能提高答对率，GRPO 就把裁图推满。这一点由第 2 项的日志核对来确认或否定。

## 4. 下一轮实验

| | 原版 GRPO（已有） | 新一组 |
|---|---|---|
| 起点 | A 的 SFT checkpoint | 同一个 |
| 奖励 | `correct` | `correct * (1.0 - 0.01 * crop_count)` |
| 其他 | 165 步，同题、同划分、同超参、同种子 | 全部相同 |

- `crop_count` 打算取环境实际执行的裁图次数（预算 8，最多扣 8%）。答错仍是 0 分，所以只有答对时才体现裁图代价。
- 评测用上一轮的 552 题（440 题分层验证集 + 112 题 V\*），每题 4 次采样，温度 0.7；正常（E1）和首次裁图换错框（E2）两种条件都跑。

**要看的指标：**

| 目标 | 指标 |
|---|---|
| 减少无效裁图 | 直答率；平均裁图数；与之前某框几乎重合的重复裁图比例；“看清了还要再裁、把对的改错”的样本数 |
| 保住答题 | 总体与分层准确率；SFT 原本直答对的题在 GRPO 后的准确率 |
| 保住纠偏 | E2 中重裁比例、回到目标比例、扰动造成的净掉分 |

**预测与停止条件：**
- 预期：直答率回升，平均裁图数下降，准确率与原版 GRPO 持平（区间跨 0），E2 重裁比例仍接近原版。
- 若直答仍接近 0：说明 1% 的代价太小，或直答路径本身有问题（回到第 3 节第 2 项）。
- 若准确率显著下降或 E2 重裁明显减少：代价伤到了需要裁图的题，下一步考虑只对“首轮已能读出答案”的情况扣分，或减小系数。
