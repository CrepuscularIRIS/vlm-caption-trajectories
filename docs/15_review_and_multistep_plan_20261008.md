## 1. 已选清单没有同题跨模型重复；仍有同图不同题

实际正选文件有 5,277 行、5,277 个规范图像—问题键、5,277 个不同源结果路径。每题恰好选一条，未拼接不同模型的步骤。

原图组为 4,755：4,297 组各一题，428 组各两题，23 组各三题，2 组各五题，4 组各七题，1 组十七题。共 458 个组有多题，比一组一题多出 522 个任务。这符合“每题一条”的口径，并不等于每题来自一张从未重复的原图。后续划分与评估仍应按已有原图组隔离，不能把同图的不同题当成完全独立的视觉场景。

去重依据是本项目现有规范任务键、来源关联和图组登记；不声称已发现所有未知近重复或场景变体。单原图产生多次裁图属于单图任务；原题多张独立源图拼成截图，不能据此绕过单图范围。

## 2. 多步示范可以增加，但不能按教师名字或裁图次数判质量

已选工具路径 3,048 条，其中 1,800 条一次裁图、1,248 条至少两次裁图；直答 2,229 条。Astra/Gemini/K3 合计入选 766 条，其中工具路径 290 条、至少两次裁图 79 条。后一个数说明新教师对多步桶的贡献较少，并不证明其余教师的多步路径不合格。

此前定向重生成 689 题，603 条送审、446 条 KEEP，其中 287 条直答、159 条有裁图、32 条至少两次裁图。选题来自旧多步路径，并不保证新教师也需要多步。因此，重复同样生成条件，可能继续增加直答；仅提高模型档位不能保证获得需要的示范。

本轮核对发现，工具分类也是筛选代理：已选工具路径中有 118 条缺少 observed 标签，165 条记录为 direct_sufficient，569 条记录为 direct_but_needed_zoom。这些字段在批次间含义不完全一致，不自动构成错误，也不能自动证明每个动作有增益。复核重点是当时的可见证据、对象绑定和决定性动作，不另加复杂评分体系。

**建议保留当前 5,277 候选作为稳定基线。** 增补真实需要辨别目标、补上下文、扩大搜索范围或局部读数的完整示范。两条都合格时，按实际取证需要选用；原图清楚就保留直答。同一题新路径确实更好时整条替换，不能把新增候选同时叠加入训。

暂不能从当前统计推出“42% 直答过高”或某个最佳比例，也不能保证更多裁图会让 Qwen 学得更好。多步增量至少应报告：新增可用任务数、同题路径改善数、有用取证覆盖、直答转工具的实际理由，以及独立原图组增加数。

## 3. Mini-o3 原始构造能借鉴什么

核对 [Mini-o3 原文 §3.1–3.2](https://arxiv.org/html/2509.07969v1#S3.S2)：使用 6 个手工示范，驱动 VLM 执行真实 thought/action/observation 循环，按终答正确筛选，收集约 6,000 条冷启动轨迹。其原文没有把多教师逐题共识写成该冷启动流程的必要条件。

论文中的 VisualProbe 着重小目标、干扰物和高分辨率；其作用是让探索具有实际需要。cold-start SFT 激活多轮工具使用，而六轮上限和 over-turn masking 属于后续 RL 设置，不能直接当成我们的 SFT 步数要求。[论文 §3–4](https://arxiv.org/html/2509.07969v1#S4.S3)

对本项目的迁移是：用少量完整示范教行为、在合适的题上真实执行、再筛选。我们采用短证据 Caption，并继续检查关键事实与对象绑定；不把终答正确当作充分条件，也不据此恢复每步在线打回监督或要求固定裁图数。论文没有提供本项目应采用的直答/单裁图/多裁图比例。

官方 [代码仓库的 SFT 说明](https://github.com/Mini-o3/Mini-o3#stage-1-cold-start-supervised-fine-tuning-sft) 使用 Qwen2.5-VL-7B-Instruct 和 LLaMA-Factory。我们尚未验证当前候选在学生上的学习收益，不能把论文结果当作本项目已完成的验证。

## 4. 71,749 份未审记录，先离线分流，不逐份直接派模型

| 当前离线筛选条件 | 路径记录数 | 解释 |
|---|---:|---|
| 无过程审核标签 | 71,749 | 包含答错、弃答、截断、格式问题及重复任务候选 |
| 其中答对且过修正后的程序门 | 42,834 | 尚未证明过程质量；也尚未在此行排除所有来源/题意问题 |
| 上一行中有裁图 | 24,291 | 可能提供工具示范 |
| 上一行中至少两次裁图 | 10,616 | 审核优先级信号，不等于困难或有效探索 |

进一步只看四主模型、当前 train 范围、没有已知“原始图数未核”标记的未审 CPU 合格工具路径：22,954 条，涉及 12,927 个任务。去掉当前 5,277 清单中的任务后，剩 18,038 条路径、9,864 个任务，其中 6,061 题有至少两次裁图候选。

这些 9,864 题中，4,316 题此前至少两个模型族都产生过两次及以上裁图；它们只有 16 题同时已有显式 BAD 路径。这说明“必须已有 BAD”会漏掉大量根本还没审过的题。旧制 REJECTED 不在这个 BAD 数字中。

以上是待评估范围，仍可能包含 GT 冲突、已有其他 KEEP、示范曝光等情况。它不是已确认的高质量池或已派发题单。GT 冲突应先核判分、题义和可回答性，不能按多数票改 GT，也不能全部自动定为难题。

建议的轻量顺序：

1. **全量离线分流库存**：使用现有标签、程序检查、任务键、来源和裁图记录。已选候选保持独立，不被新任务阻塞。
2. **按题补审有希望的现成路径**：优先跨模型多次裁图、现有证据/绑定缺口、缺少可靠工具示范的任务；兼顾不同来源和材料，不只挑“全错”题。一个独立审查上下文处理一题，逐步只使用该步此前实际收到的视图。
3. **拒绝一条后看同题替补**：可用时停止为该题寻找更多同质路径；确有两条都合格时比较取证适配性，不盲目奖励更长者。不要求把同题四条全部完整重审才允许选一条。
4. **无合格替补且题可回答，才补生成**：Gemini 可作为主要补充，K3 在额度内用于差异化候选；仍缺可靠路径或明显困难的题再到 Astra。Astra 额度充足时可以提前承担修复，但不能预设它必须产生更多 crop。生成不提供 GT、正确目标或指定错误步骤。
5. **CC 独立过程审核并择一**：Sonnet/Opus 的具体调用由用户管理，审核与生成上下文隔离。关键证据争议单独复核；同一模型自身的反驳轮不能冒充独立多模型验证。始终记录 KEEP/WEAK/BAD/UNRESOLVED 和实际审核覆盖。

第一轮建议从上述范围中按来源和裁图区间取约 500–1,000 题，先看每审 100 题新增多少有用多步 KEEP、多少只需换选、多少是题义/判分问题，再决定下一轮规模。这是预算建议，未执行。若后续要全量覆盖，按同一题级队列分批推进，不以“把所有 71,749 条审完”作为现有数据交付的前置条件。

## 5. 与既定指导原则的对应

| 原则 | 此方案如何满足 |
|---|---|
| 规模已够，优先筛选 | 先审已有工具候选，不给全池新增教师 |
| 一题一条完整轨迹 | 新路径替换旧路径；同题不重复增加训练条数 |
| 保留合理直答 | 原图证据足够时无需裁图，不为比例强造动作 |
| 轻量扩充 | 保持 Caption 与真实动作协议，差异体现在样例中 |
| 一致性不能降低过程要求 | 答案与多次裁图只影响排序，不直接授予 KEEP |
| 合理搜索未命中可以保留 | 如实说明、换区取得证据；不因两次未命中直接淘汰 |
| 错误前缀恢复单列 | 不把错误陈述全段作为 clean SFT 正监督 |
| GT 优先、先查可回答性 | 不用多数票改标，不对刷不出 GT 的歧义题持续生成 |

当前主要缺口是**库存进入过程审核的覆盖，以及多步动作是否真正有用的统一核对**。补生成可以改善已确认的缺口；它不是替代库存筛选的第一步。
