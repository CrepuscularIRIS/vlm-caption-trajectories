# 结果汇总：卡 A / 卡 B、KL、两个基线（2026-10-19）

按导师 10-18 的要求整理：
- 结果用论文表格记录，分下游 benchmark（表 1、表 2）。
- 每组实验报告实际训练 token、更新次数、rollout 开销（表 3）。
- 补两个基线：SFT cold-start w/o RL；只用图片加最终答案的 SFT cold-start w/ RL（表 1 第 1 组）。
- rollout 按全对 / 全错 / 有对有错分组统计（表 4）。

方法设计见 [docs/26](26_cards_ab_groups_kl_20261018.md) 与 [`pipeline/grpo/v51_cc/`](../../pipeline/grpo/v51_cc/)。单种子，结论都是初步的。

## 设置

- **学生模型：** Qwen3-VL-4B-Instruct。所有 GRPO 都从对应的 SFT 起跑，165 步，每步 12 题 × 16 条 rollout，lr 1e-6，2 张 RTX Pro 6000。除 KL 组外均不加 KL。
- **评测 E1：** 552 题 × 4 次采样，T=0.7，同种子，按训练规则判分。服务器上的评测题只有四个来源：MME-RealWorld 339 题、MMMU-Pro 39 题、V* 112 题、WorldBench 62 题；HR-Bench、TreeBench、VisualProbe 不在其中。
- **评测 E2：** 同 E1，但把模型第一次裁图的框换成偏移框（首裁扰动），看能否从回执中纠正。
- **统计：** 配对差值按题 bootstrap，2,000 次，95% 区间。MMMU-Pro 与 WorldBench 题数少，单格差 3–5 个点在噪声内。
- **checkpoint：** RL 组都取第 160 步（与原版 GRPO-A 一致）；第 165 步另列。

读法：
1. 策略更新几乎全部来自有对有错组，全对组和全错组的 advantage 为 0，与导师说的一致。
2. 有对有错组里，直答比裁图低 12–17 个点，平均 advantage 为负。所以只看对错的奖励本身会把直答往下压，裁图数随训练上升；这一点在对照组里同样成立。
3. 答案式基线有 30% 的组全错、47% 的组全对，只有 24% 的组产生梯度，而且组内都是直答。所以 RL 只能在"选哪个字母"上更新，学不出裁图。

## 主要发现

1. **caption + 裁图轨迹是收益的来源。** 同题同图下，答案式 SFT 比库 A 的 caption SFT 低 9.4 个点（.458 vs .552），V* 上低 26 个点。加 RL 后差距扩大到 17.2 个点（.492 vs .664）：RL 给答案式模型只加了 3.4 个点，给 caption 模型加了 11.2 个点。答案式模型在 SFT 和 RL 中从未裁图。
2. **KL（0.01）没有改变准确率和效率**（−1.1 个点，区间含 0；裁图 +4%），但对首裁扰动最稳（E2 只掉 0.3 个点，其他组掉 1.4–3.6 个点）。KL 损失只从 0.002 升到 0.035，说明在这个训练规模下策略本来就没有离 SFT 太远。训练内验证的领先（第 160 步 0.625 vs 0.616）没有在 E1 体现。
3. **卡 B 的效率最好：** 准确率与原版持平（−0.8 个点，区间含 0），裁图少 37%、token 少 26%，略优于 crop-floor λ=0.025（.649 / 1.38），但训练开销多 65%。卡 A 准确率最高（.666），但只省了 9% 的裁图。
4. **固定裁图代价（crop-floor）最省开销：** 裁图少 40–47%，训练最快，准确率低 1.5–1.7 个点（区间含 0）。

## 未完成与已知问题

- **单种子。** 卡 A/B、KL 与原版之间的准确率差都在 1–2 个点内，需要第二个种子才能区分。
- **评测覆盖不全：** 评测只覆盖四个来源，没有 HR-Bench / TreeBench / VisualProbe。
- **SFT token 缺失：** 库 A 的 SFT 训练 token 待离线统计。
- **已修正的事故**（详见 CHANGELOG）：答案式模型由 LLaMA-Factory 导出的 `config.json` 缺 `rope_scaling`，第一次评测（.424）因此作废，修正后重评为 .458；为此停掉的对照重跑已在答案式 GRPO 之后重新开始。
- **磁盘：** 服务器磁盘 96% 已用。之后的 run 只存模型权重；已结束 run 的优化器状态（463 GB）待决定是否删除。
