# C08 — Re-engineer Alignment for New Domain
_parent: **Re-engineer the Interface, Keep the Backbone** (`adapt_interface_not_backbone`)_ · secondary: Recast Everything Into One Shared Format (`unify_into_shared_format`) · n=38 (oral 0, spotlight 3, poster 22, reject 13)

## Tactical pattern

The shared move is to extend a strong pretrained system to an input domain, granularity or regime it was not built for by redesigning the bridge between that input and the system's existing interface, while leaving the backbone largely frozen or lightly tuned. The bridge takes several recurring forms: lifting a new structured input into features the existing encoder already produces (aggregating features from rendered views, rendering a non-native signal through a differentiable renderer, fusing a pretrained geometry or auxiliary encoder in parallel); representing a new reference type in the interface's own vocabulary (positions as text tokens plus pooled continuous features, discretized input codes added to the vocabulary, a placeholder token replaced by sub-region features); disentangling what the alignment stage must learn (structure versus content, concept versus background) so the bridge stops relying on a shortcut; conditioning or routing the bridge on the instruction, language or modality (instruction-aware queries, routed adapters, expert modules); compressing or caching input tokens so a new regime (long streams, large scenes) fits the context; and aligning the interface's own internals (attention maps, hidden states at the layers that trigger a behavior) to supervision instead of attaching a new decoder. The load-bearing artifact is the bridge design plus the paired data used to align it, and the headline result is that the adapted system handles the new domain with far less data or compute than a native model while preserving prior abilities.

## Step-by-Step

1. Diagnose the specific mismatch between the new input and the existing interface, with evidence. Measure where it breaks: the alignment stage never taught recovery of underlying values, a modality's hidden states drift from equivalent text at the layers that trigger a behavior, attention over the input shifts layer by layer, a component-wise probe shows the bottleneck is the backbone rather than the encoder, or tuning succeeds through a text shortcut rather than the new input. Papers that skip the diagnosis and simply port the standard alignment recipe to a new domain are read as incremental technical reports; papers whose diagnosis is vivid but disconnected from the method are asked to close that gap.
2. Design a bridge that targets exactly that mismatch and expresses the new input in a form the backbone already consumes. Lift into the existing feature space, encode new references in the interface's own vocabulary with a continuous complement, separate the components the alignment must learn, condition the bridge on the instruction, or compress/cache so the regime fits. Keep the backbone's native pathway intact (parallel branches, residual or routed adapters, frozen weights) so prior abilities survive. Check what is genuinely new against the nearest existing bridge — anchor tokens, interleaved region features, attention supervision and adapter routing have prior variants, and reviewers reject near-duplicates.
3. Build or synthesize paired data that aligns the bridge, and validate it. Generate data from rendered views, structured page sources, simulators, metadata or a strong generator, but audit its quality (human spot checks, per-class analysis), check for leakage between the generation source and evaluation sets, and avoid machine-generated references that merely encode an existing algorithm's output. Keep the data lean where possible; data efficiency is a recurring source of praise.
4. Isolate the bridge from data, scale and backbone in the comparison. Train baselines on the same generated data, hold the backbone and data volume fixed when comparing representations, ablate each bridge component (and simpler alternatives such as plain adapters, text-only replay or a uniform alignment), and run more than one backbone family. Unfair comparisons — a stronger backbone, much more data, an extra input sensor, an auxiliary detector that injects the very signal being claimed — are a direct cause of rejection.
5. Evaluate on established external evaluation sets plus retention of general ability, and report cost. Go beyond the authors' own evaluation set and multiple-choice formats on the training distribution; test out-of-domain and open-ended use, measure forgetting of prior abilities, and report latency, memory and added parameters. Scope the claim to the domains and formats tested, and state limitations such as single-domain data or hand-tuned window sizes.

## When to pick this one

Reach for this when a strong pretrained system exists, the target input does not fit its native interface, and you can name and measure why it does not fit — and your fix is a bridge that keeps the backbone and its existing abilities intact. If the domain is merely new but the input already fits the interface, the work is instruction tuning on new data (and will be judged as such); if you cannot show the bridge rather than the data does the work, the contribution reduces to a resource paper.

## Tactical failure mode

The dominant failure is the recipe port: the standard encoder-projector-tuning pipeline moved to a new domain with a generic encoder and synthetic instructions, which reviewers call incremental regardless of being "first" in that domain. The second is confounded attribution: the new representation is compared against baselines with a different backbone, less data, or fewer input signals, so the bridge's contribution is never isolated. The third is near-duplicate novelty: the bridge closely matches an existing anchor-token, region-interleaving, attention-supervision or adapter design, and gains over it are marginal. The fourth is narrow or self-referential evaluation — one backbone, one domain, the authors' own evaluation set or multiple-choice on the training datasets, machine-generated references — plus predictable conclusions from controlled studies that only re-confirm known orderings (fine-tuning beats prompting). A candidate can self-check: is my bridge motivated by a measured mismatch, does it beat the closest existing bridge under matched data and backbone, and does the adapted system keep its old abilities on external evaluations.

## Examples
### Accepted lessons
- Lifting a new structured input into the feature space a pretrained encoder already produces — aggregating features from rendered views and expressing positions as interface tokens — lets an existing system gain a new modality without a native encoder.
- A hybrid representation of a sub-region, discrete coordinates written in the interface vocabulary plus continuous features pooled from that region, serves both region-in and region-out tasks through one interface.
- Disentangling the structure from the content during alignment gives a consistent structural representation that can then shrink inference to an evidence-grounded sub-part, with very little alignment data and no external tools.
- Locating the layers whose hidden states trigger a behavior and showing the new modality deviates from equivalent text there turns a vague transfer failure into an alignment target that a lightweight fix can close.
- Probing components separately to show the backbone rather than the encoder is the bottleneck licenses training the backbone on cheap synthesized single-modality data and transferring the skill without new-domain data.
- Making the bridge differentiable end to end, so the downstream loss shapes how the non-native input is rendered, is preferred over a fixed hand-designed conversion.

### Reject lessons
- Porting the standard alignment-and-instruction recipe to a new signal domain with a generic encoder, where references are themselves machine-generated, is judged incremental and possibly mere imitation of existing algorithms.
- A new scene or input representation evaluated against baselines with a weaker backbone and much less data, without a controlled ablation isolating the representation, is rejected as an unfair comparison.
- Supervising the interface's own attention or adding an anchor token for localization is read as a simplified variant of existing designs when gains over the closest method are marginal and a special-token alternative performs as well.
- Evaluating only multiple-choice answering on the same datasets used for training, with one backbone and one domain, leaves open-ended use, out-of-domain transfer and retention of general ability unproven.
- A careful controlled comparison of adaptation regimes whose conclusion is predictable (fine-tuning beats training-free prompting) does not clear the bar, however well organized.
