# C09 — Recast Inputs Into Native Instruction Format
_parent: **Recast Everything Into One Shared Format** (`unify_into_shared_format`)_ · secondary: Synthesize Supervision From a Privileged Exact Representation · n=12 (oral 0, spotlight 1, poster 8, reject 3)

## Tactical pattern

The shared move is to keep a capable pretrained base system largely unchanged and instead convert whatever is new — a specialist signal, a family of related input settings, a set of heterogeneous tasks, or an untapped side signal — into the one input format that system already consumes, then instruction-tune on the converted data. The conversion takes a few recurring forms: render raw specialist signals into a view the base system's native encoder can read; express several related input settings as special cases of one general interleaved sequence template; flatten heterogeneous task contexts and outputs into a single generation stream; or run fine-grained detectors, measurement extractors and rule-based knowledge guides over raw samples, turn their outputs into natural-language descriptions, and have a strong generator write instruction data grounded in those measurements. Abundant signals that are normally discarded (passively logged audience responses, non-semantic cues lost by a cascaded front-end) can also be recast as auxiliary instruction tasks. Training is typically a short alignment stage followed by joint instruction tuning, with no or minimal architectural change. The load-bearing claim is that the bottleneck was the data format and missing paired supervision, not model capacity, so one unified model replaces per-setting specialist pipelines and shows cross-setting transfer.

## Step-by-Step

1. Diagnose that the limitation is a format or supervision gap rather than a capacity gap, and state the shared structure being exploited. Show that specialist pipelines or narrow classifiers exist because inputs, tasks or settings were treated as distinct, and name the one template that covers them. Papers whose motivation for the new setting is unclear — where reviewers can recast the "new capability" as an existing skill reachable by a simple front-end — do not survive.
2. Define a conversion into the base system's native format that preserves the information the target task needs. Choose rendering, interleaving or detector-to-description conversion so that decisive cues survive; argue (or ablate) what the conversion might lose, and keep architecture changes minimal so the unification claim stays clean. When raw input is fed end to end instead of a cascade, show what the cascade discarded and that a cascade-plus-metadata baseline does not match it.
3. Generate instruction data at scale from privileged, measurable sources, and validate its quality independently. Anchor generated descriptions and explanations to detector outputs, extracted measurements or a rule-based knowledge guide so each statement is traceable, then quantify label quality against experts or held-out annotation. Unvalidated model-generated data — ungrounded plans, wrong descriptions, noise propagated from large teachers — and evaluation by the same generator family were the core reasons rejected members failed and the main ceiling on accepted ones.
4. Train with a short alignment stage then joint instruction tuning on the unified data, and separate the effect of the format from the effect of more data. Include data-matched controls (same volume without the new structure or signal), component ablations, and blind or single-channel baselines, and check that capabilities on the original native setting are preserved. Gains that may come from data diversity or volume rather than the claimed structure are the standing objection.
5. Evaluate breadth and transfer against specialized baselines, and size claims to the evidence. Show cross-setting or cross-task transfer, compare with task-specific state-of-the-art (not only general or outdated models), use human or expert scoring where a model judge would be circular, and test more than one backbone or domain before claiming generality. Generalist framing with weak, under-baselined downstream results reads as overreach.

## Differentiation within parent

- vs **Shared Interface Bridging Planning and Control** (C18): C18 unifies what the model emits — an action vocabulary, program nodes, latent plans or state rollouts that an executor or controller consumes — and its payoff is acting across environments. C09 unifies what the model ingests: it recasts signals, settings and tasks into the base system's native input format and builds instruction data for understanding, prediction and explanation, with transfer across input settings rather than across executors.

## When to pick this one

Pick this when a strong base system already handles one input format well, the target signals or settings share structure that can be expressed in that format without losing the decisive cues, AND you can produce paired supervision cheaply from detectors, measurements or existing annotations whose quality you can verify. If the conversion discards the information the task depends on, or the only supervision source is an unvalidated generator, the tactic reduces to data augmentation plus tuning.

## Tactical failure mode

The dominant failure is unvalidated synthesized supervision: instruction data written by a language model from structured descriptions or detector outputs, never checked against experts, and often evaluated by a judge from the same model family, so reviewers cannot tell whether gains reflect correct labels or merely more and more diverse data. A second shape is an unmotivated setting — the recast capability looks like an existing skill (e.g. reading text that has been moved into another channel) solvable by a simple front-end, and the obvious pipeline baseline is missing. A third is generalist overreach: one model is claimed to cover many tasks, but downstream results are weak, partial or compared only against general-purpose models. Self-check: is the generated data validated independently of the generator; does a data-matched control isolate the effect of the unified format or new signal; and does the converted setting require a capability that a cascade or simple front-end cannot supply?

## Examples
### Accepted lessons
- Expressing several related input settings as special cases of one general sequence template, and jointly tuning an unchanged model on a compiled dataset in that format, can unify capabilities and produce emergent cross-setting transfer while preserving the original setting's performance.
- Rendering raw specialist signals into a view the base system already reads, and replacing absent expert annotation with a programmatic engine whose bespoke detector supplies structured labels, can reframe a narrow classification field as open-ended interpretation.
- Tying generated explanations to measurable parameters extracted from the input and passed through a rule-based knowledge guide turns synthesized instruction data into traceable evidence, and expert assessment strengthens the case.
- Abundant signals normally discarded as noise, such as passively logged downstream responses, can be recast as auxiliary instruction tasks — a data-matched control is what makes the claim that the signal (not the volume) helps credible.
- Feeding the raw signal end to end instead of through a cascaded converter preserves non-semantic cues that become decisive for personalization, provided a cascade-plus-metadata baseline is addressed.

### Reject lessons
- A generalist model trained on instruction data synthesized by a language model from structured scene descriptions is rejected when the generated data is visibly unreliable, design choices are justified only by model judging, and downstream action results are weak or under-baselined.
- Moving an instruction into a different input channel and tuning on rendered examples reads as an existing recognition skill rather than a distinct capability unless a front-end baseline and a clear application scenario are provided.
- Boosting a prerequisite skill with many synthetic auxiliary tasks before target adaptation fails when the method is unclear, gains are not separated from added teacher-generated data, and reproducibility depends on large external teachers.
