# 设计思路：先构造真实示范，再验证训练收益

## 目标与范围

当前任务是单张静态图上的多步观察。模型接收问题与原图，可以调用 crop，再结合已收到的视图作答。我们希望构造适合 SFT 的训练示范：动作确实执行、caption 可由当时证据检查、不同难度与行为均有代表。

一条好的轨迹未必很长。清晰表格可以直接回答；小字需要一次局部观察；分区计数可能需要保持多个小计；相似候选需要核查区分条件；坏 crop 可能需要恢复上下文。**轨迹长度不是视觉取证质量。**

## 原始 Caption 与 BundleAudit 的关系

原始设计材料位于上游项目的 `huggingface/Caption/`，包含多个方案草稿、Dots、提示词代码与交付包。`BundleAudit/` 是其后的更新，特别考虑后续 RL 所需的证据更新、真实前缀、分支与监督记录。

本公开仓库按当前问题重新组织上述材料，不将历次草案的相冲突阈值全部当成现行规则。源码、提示词和结果快照可查哈希；私有讨论记录没有逐字公开。

|层次|核心内容|当前地位|
|---|---|---|
|原始目标|行为规范 → 适合场景 → 真实轨迹 → 基础核验与筛选|构造主线|

## 五个需要分开的判断

1. **信息存在**：图像中有没有可区分的内容？原始尺寸大不等于读得清。
2. **取得证据**：第一次作出关键断言时，已经收到的图像是否支持它？
3. **绑定与保持**：读数属于哪个对象、哪一行列、系列、图例或单位？先前事实能否继续使用？
4. **使用与更新**：前提改变后，旧结论是否撤回，必要计算是否重做？
5. **训练与因果效果**：训练是否改善行为？受控改变证据是否改变决策？这需要另外的实验。

终答一致只能覆盖其中很小一部分；写了 REVISE 也不代表进行了有效修正。反过来，正确的旧 caption 可以是有效视觉记忆，不能一概视为语言捷径。

## 什么样的“精细设计”值得保留

值得保留的是能改变数据质量的规则：真实 crop、视图来源、已收证据边界、实例绑定、关键事实复核、错误前缀另池。它们让读者能回答“这一步为什么合理”。

暂不继续增加每步固定检查表、行为关键词数量、无条件重看或复杂评委面板。也不为了让一条轨迹显得复杂，要求原本清楚的题先猜错再改正。当前协议已经足够细；不足的是有证据支持的行为实例。

## 构造示范与测量自主能力

通用教师提示、无答案泄漏的题型提示以及独立多源筛选可以用于构造 SFT 数据。它们不等于学生在完全相同输入下的自主能力。

当前生成阶段使用题型 Hint，导出时去掉这些 Hint，记录为教师脚手架蒸馏。状态特定反馈若参与生成，必须保留并标记来源，不能无痕删掉后称为自主轨迹。原始错误不能事后润色成“当时只是猜测”。

本阶段交付是可审阅的种子轨迹与方法记录，不是能力证明，也不是训练完成报告。
