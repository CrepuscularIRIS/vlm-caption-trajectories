# Caption v5.1：短证据与真实动作

## 单步格式

以下是**格式示意，不是生成样本**：

```text
<think>
Step N | re_examine
[observation_k] 已遇到的候选还缺少一个区分条件，下一视图检查该条件。
</think>
<grounding>{"bbox_2d":[x1,y1,x2,y2],"source":"observation_k"}</grounding>
```

每步一个短证据块与一个动作。通常 1–3 个短句，必要时增加更新或计算行。工具只有 crop；终答使用 `<answer>...</answer>`。规范中的 `<think>` 是可见短证据文本，不能与 API 私有 reasoning 字段混淆。部分 API 使用 `<caption>` 标签；运行器解析后按导出格式规范化。

## 行为语义

|标记|何时使用|需要说明|
|---|---|---|
|locate|尚未找到候选或证据区域|已有可见锚点，以及寻找什么|
|re_examine|已遇到候选，细节或绑定仍未决|具体未决项与新视图的作用|
|fallback|当前搜索分支无效、截断或缺少上下文|失败范围与新区域改变什么|
|commit|事实、绑定及必要运算足够|决定性证据；允许第一步直接回答|
|abstain|关键不确定无法通过剩余合理观察消除|缺失的事实或绑定；回答 UNCLEAR|

前 3 类对应 crop，后 2 类对应终答。几何重叠、返回原图或框变大本身都不能定义行为。

## 更新与计算

- `HOLD:` 保留先前已有证据、当前仍需使用的事实。新图不必再次显示旧事实。它不要求先发生错误。
- `REVISE:` 由具体视觉依据改变旧候选、读数、计数或绑定，写明旧值、新值及依据；撤回或重算依赖旧前提的结论。
- `CALC:` 记录必要短计算，输入已有来源。
- `RULE:` 记录必要公式或约定，区分题给条件、图上读数与推算结果。

这些是事件对应的更新行，不是每步检查表。第 1 步没有旧事实可 HOLD/REVISE；fallback 也可能只是搜索未果，并不需要修正先前断言。

## 坐标与视图

动作框使用相对 source view 的 `[0,1]` 坐标。环境将框映射回原始全分辨率图实际裁取，记录父视图、原图区域、源像素、实际呈现像素、图像哈希。框的最小宽高及像素扩展由运行器执行。

**裁图坐标只放动作，不写进 caption。** 当前 clean 池将 `coordinate_talk` / 未解决坐标风险作为门槛。图表中的 x 轴值、图像测得的物理量不是同一概念；检测器有专门区分，但本批检查不能保证未来永不误判。

引用只能来自本步之前已收到的视图。新 crop 在动作后返回，因此不能倒过来支持动作前的确定读数。放大不增加源像素，但可能改善显示尺度或恢复上下文；不能机械认定放大一定无效，也不能据此宣称获得新细节。

最多 8 次 crop 加一次终答；实际预算可以小于 8，甚至为 0。已充分就停止，不为了配额制造核验动作。
