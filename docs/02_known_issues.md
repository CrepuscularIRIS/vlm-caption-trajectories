## 一、实验细节

### 1.1 题集与条件

题集是 obsbench 主池 935 题：V* 191、TreeBench 399、O3Bench 345。有分的为 934 题，Astra 有 1 题协议失败。

强模型 Astra（gpt-6-astra）在同一批题上跑了四个条件：

| 条件 | 做法 | 采样 |
|---|---|---|
| 正常 | caption v5.1 协议，裁图预算 8，temperature 0.7 | 1 次 |
| 禁止裁图 | 同上，裁图预算 0 | 1 次 |
| 换整图 | 原图换成同数据集另一题的图，题面不变 | 1 次 |
| 只给文字 | 只给题面与选项，要求给出最可能的选项 | 3 次 |

- 弱模型：Qwen3-VL-4B 的各个检查点，与 Astra“正常”条件用同一协议，只换生成模型（§1.2）。
- MME-RealWorld 子类准确率：来自漏斗池的全量运行。GLM-5.3-flash（effort high）、GPT-5.6-Sol（effort low）、GPT-6-Luna（effort low）各约 16,170 条。
- 以下统计只读已有结果文件，没有调用模型。

### 外部 baseline 源码（接入前要处理）

- **Mini-o3**：工具解析对 bbox 文本直接调用 `eval()`；硬编码了 Qwen2.5 的 token ID。适配时改为字面量解析并做范围校验。
- **DeepEyes**：工具 schema 的 required 字段与 `bbox_2d` 不一致；不保存每轮的 token 用量。
- **Pixel-Reasoner**：取值含 1.0 的归一化 bbox 会被当成像素坐标；训练工具错误标志的跨组索引少了偏移量。
- **AdaptVision**：默认评测不开工具；`max_tokens` 被硬编码为 1600。
- **CounterCredit（本地适配）**：成本表把 GPU 数写死为 2，并且把日志行数当成更新次数。
