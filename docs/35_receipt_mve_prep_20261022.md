| 检查 | 结果 |

| 版本 | 记录了 SFT-A 的 config / tokenizer / processor、各插件文件、EasyR1 commit 和本地补丁的 sha256 |

## B：看图审阅材料（`logs/mve/states.json`，代码 `pipeline/eval/mve/build_review.py`）

- **候选：** 40 个状态，来自固定 SFT-A 在 RL 训练题上的裁图分支轨迹。设计事先写死，种子 20261022：
  - 首裁 20 个、后续裁 20 个；
  - 每类旧轨迹答错 12 个、答对 8 个；
  - 题目互不重复。
- **复原：** 用裁图环境和训练 / 评测时的图像处理器（max 589,824 像素）复原了学生实际收到的输入，40 个全部成功，每个复原出的框都与记录一致。每个状态包含：
  - 之前看过的各个视图；
  - 真实回执 **T**；
  - 对照回执 **C**：同一个绝对框，从学生已经看过的那张源视图里裁出，再重采样到 T 的尺寸。
- **不适合检验新细节的 7 个状态：** s06、s20、s26、s29、s33、s35、s38。它们的细节增益 ≤ 1.05：T 的源像素并不比 C 多，T 和 C 本来就没有差别。
- **图像不进公开仓库：** 审阅页面在服务器 `evidence/mve_prep_20261022/review/index.html`。每题先显示问题、历史和图像；旧的续写和最终答案折叠在后面，看完图、记下事实之后再打开。
- **标注表：** `logs/mve/annotation_template.csv`，每题要填：
  - T 里有没有新的可见事实，这个事实是否需要；
  - 学生之后是否正确写出了它，后面有没有用错；
  - 归类：冗余 / 必要 / 证据没用好 / 没取到证据或被误导 / 未知；
  - 是否适合进入诊断。

## 看图标注结果（10-22）：门槛没过，C 不启动

**说明：** 这次标注是 Codex 模型逐图审阅（状态 `complete_model_reviewed_not_human_gold`），**不是人工标注**。
- 每题先看历史视图、T 和 C，写下事实，再展开旧续写。39 题是这样做的，s00 提前看到了标签，已排除在门槛之外。
- 汇总在 `logs/mve/annotation_summary_codex.json`；逐题记录含题面和图像内容，不公开。

| 类别 | 数量 |
|---|---|
| 冗余（T 相对之前的视图和 C，没有可确认的、和答案有关的新细节） | 19 |
| 没取到证据或被误导 | 10 |
| 未知（如车辆运动这类单帧判断不了的题） | 9 |
| 必要 | 1（s23，题意有歧义） |
| 证据没用好 | 1 |

**门槛：** 要求至少 8 个状态"有必要的新事实，且旧轨迹答错"。实际严格算 0 个，宽松算 1 个，所以 C 不启动。结论是"这批材料不足以检验"，**不是**"信用分配方向无效"。

"冗余"在这里只表示没有确认到必要的新细节，**不证明学生不需要这次裁图**：重新放大和聚焦本身也可能有帮助。

**观察到的另一类失败**（这是假设，没有证明成因）：主要问题是**已有证据没用对**，而不是缺新细节：
- 读错已有证据（s33、s36）；
- 行列绑定错（s16）；
- 读对了却选错选项（s09）；
- 偏离题目目标，回答了另一个字段（s39）；
- 终答正确，但把回执里没有的内容说成看到了（s13、s20）。

另外，s10 是新细节被正确使用的正对照。

**限制：**
- 样本来自 SFT-A，不是 RL 之后的策略，而且是分层挑选的，比例不外推。
- 只有一位模型审阅者。
- 导师要求的"自己看看"仍需要人来完成；最小做法是人工抽看 s23、s09、s16、s33、s36、s39。
