# 配对回执诊断的准备：工作包 A（零 GPU 审查）与 B（看图审阅材料）（2026-10-22）

这是 [docs/34 第 6 节](34_report_for_mentor_20261022.md)方案的前两步，在 Open Scientist study `rl-objective-credit` 中记为诊断步骤 011，没有用 GPU。

## A：零 GPU 审查（`logs/mve/audit_a.json`，代码 `pipeline/eval/mve/audit_a.py`）

| 检查 | 结果 |
|---|---|
| 版本 | 记录了 SFT-A 的 config / tokenizer / processor、各插件文件、EasyR1 commit 和本地补丁的 sha256 |
| 手写"四格"规则 | **确认只分两格。** 对每一种前后标签、A 的正负两种情况穷举：改变裁图后的标签，输出从不改变（v51_credit，未训练） |
| dV 中心化 | 对 dV 本身做组内中心化恒为 0（同一题的 dV 相同）；对 s·dV 中心化，只在全组首轮动作相同时为 0 |
| 真实 token 片段 | 5 条 SFT-A 裁图分支、14 轮，按 WORD 头、caption、动作（`<grounding>` 或 `<answer>`）和结束 token 给出 token 区间。**发出裁图的那一轮，caption 写在它自己的回执之前**，只能用到之前看过的视图 |
| 仍未成立的结论 | E[A·N] 的符号不等于更新方向；E[c²] 不等于梯度方差；读者判的 RR / WW 不等于"冗余 / 必要但失败"；.777 一致率缺少"自然对自然"的参照；DB 门槛失败不等于方法失败 |

## B：看图审阅材料（`logs/mve/states.json`，代码 `pipeline/eval/mve/build_review.py`）

- **候选：** 40 个状态，来自固定 SFT-A 在 RL 训练题上的裁图分支轨迹。设计事先写死，种子 20261022：
  - 首裁 20 个、后续裁 20 个；
  - 每类旧轨迹答错 12 个、答对 8 个；
  - 题目互不重复。
- **复原：** 用裁图环境和训练 / 评测时的图像处理器（max 589,824 像素）复原了学生实际收到的输入，40 个全部成功，每个复原出的框都与记录一致。每个状态包含：
  - 之前看过的各个视图；
  - 真实回执 **T**；
  - 对照回执 **C**：同一个绝对框，从学生已经看过的那张源视图里裁出，再重采样到 T 的尺寸。
- **不适合检验新细节的 7 个状态：** s06、s20、s26、s29、s33、s35、s38。它们的细节增益 ≤ 1.05：T 的源像素并不比 C 多，T 和 C 本来就没有差别。
- **图像不进公开仓库：** 审阅页面在服务器 `evidence/mve_prep_20261022/review/index.html`。每题先显示问题、历史和图像；旧的续写和最终答案折叠在后面，看完图、记下事实之后再打开。
- **标注表：** `logs/mve/annotation_template.csv`，每题要填：
  - T 里有没有新的可见事实，这个事实是否需要；
  - 学生之后是否正确写出了它，后面有没有用错；
  - 归类：冗余 / 必要 / 证据没用好 / 没取到证据或被误导 / 未知；
  - 是否适合进入诊断。
