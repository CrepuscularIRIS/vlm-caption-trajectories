# 从题目到 SFT 轨迹

## 1. 冻结题目与独立单位

当前批次使用冻结的 train 图组。划分以来源原图组为单位，同一场景的多个题目、教师变体和 crop 不应作为独立证据重复计数。30 个题目来自 30 个不同 group_id。

在生成前固定题目、答案规范、split、材料类型和运行预算。正式金标只用于离线判分。题目存在标签争议时单列；不能为了收下一条行为漂亮的轨迹改 gold。

补覆盖 6 题预登记了 hold/revise/fallback 各 2 个题槽。[清单](../data/snapshot.json)中的 slot 表示抽样意图，尚不等于存在已认证的行为机会。

## 2. 独立生成与原始记录

|批次|生成配置|保存轨迹数|
|---|---|---:|
|smoke24|K3 low|24|
|smoke24|GLM|24|
|smoke24|Sonnet，部分题第三来源|7|
|cover6|K3 default|6|
|cover6|Sonnet|6|
|合计||67|

K3 low/default 是同一模型的不同配置，不能把它们当成两个独立模型家族。模型名与 effort 在快照中按原记录保留，不能仅从输出长短推断推理档位实际生效。

每个生成器只看问题、原图、公共协议、题型 Hint、自身历史和真实工具返回；不看其他生成器的答案、gold、审计结论或未来视图。裁图由环境实际执行，失败、截断、格式拒绝与重试分别留档。格式重采样不算额外独立题目。

## 3. 离线判分与候选选择

先做冻结答案规范下的终答判分与协议检查，再进入审计。本轮要求至少两个生成来源答对，才安排候选审查；这一实现上的门槛不等于两条过程均已经认证正确。

候选排序优先显式 HOLD、REVISE、fallback，再看风险与裁图数。标签只用于调度优先级；其真实性仍需审查。最多审有限个候选，遇到第一条自动通过就停止。

## 4. 审核拆成三个问题

|检查|输入|回答的问题|局限|
|---|---|---|---|
|终答盲读|题目及选定证据视图；没有生成答案或 gold|独立读取是否支持最终结论|当前最多取 3 个终答引用视图；可能丢必要旧视图|
|结构/依赖审查|问题、轨迹、所有已收视图|错绑定、无据翻转、更新与依赖撤回|全轨迹回顾不能认证早期可见性|
|关键事实盲读|每条抽 1–3 个关键事实，仅给该步之前已收视图|首次读数/绑定当时是否有据|抽查不是穷尽；事实抽取本身可能漏项|

盲读先冻结读取结果，再与短 claimed 值比较。文字比较处理同义表达，不是视觉真值 oracle。SUPPORTED、CONTRADICTED、INSUFFICIENT 必须区分；不同模型也可能犯相关错误。当前已避免同一模型审自己的轨迹。

事实比较曾把整句话当 claimed，造成许多过严判定；当前改为短值，必要时再做文字比对。空 JSON 也不再默认通过。不过 schema 校验不能证明抽取覆盖了每次应有的 HOLD/REVISE。

## 5. 人工终裁与导出

这次最终选择明确使用人工终裁表，只有 KEEP 才导出。公开脚本的 `--manual` 参数仍是可选项，因此调用者应注意：**本轮启用了人工门，不代表脚本任何调用方式都会自动启用它。**

保留选中教师的一条完整路径，不将多个教师的好步骤拼接。当前实现先停在首条自动通过候选，之后若被人工否决，不会自动审完该题其他备选，这是已知召回边界。

|池|用途|当前数量口径|
|---|---|---|
|clean_sft|无已知关键错误的完整正例路径|16 条导出，16 图组|
|recovery_continuation|真实确定性错误前缀之后的合格修正，仅监督后续|空；尚未验证对应 mask|
|calibration_or_ambiguous|单源、标签疑点、审计或人工未通过|14 个题目级选择记录|
|counterfactual_diagnostic|明确标识的干预诊断|本轮未产生|

当前 `recovery_like` 只是粗分流逻辑，不是错误跨度与依赖修复的完备验证器。

## 6. 学生格式与预处理

ShareGPT 导出保留系统规则、图像输入、真实工具回执和助手动作，去掉生成阶段题型 Hint，并在 manifest 中记录。回执与用户输入是上下文；clean 池助手短 caption 与动作是监督对象。

CPU 预处理报告验证了这 16 条在固定 Qwen2.5-VL / LLaMA-Factory 配置下的标记数量、图像数量与长度。它没有验证训练收益，也没有用不存在的 REVISE/fallback 样例覆盖相应类型。详见[训练衔接](06_sft_rl.md)。
