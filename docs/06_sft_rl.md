# 从当前轨迹到未来 SFT / RL

本页是训练设计与待验证项，不是已完成训练报告。

## clean 整轨迹监督

clean 池保留一条真实完整执行路径，监督助手的短 caption 与动作。系统规则、题目、图像、工具回执作为上下文，不作为助手目标；图像与历史顺序应和生成时一致。

题型 Hint 可作为教师通用脚手架，当前导出会去掉并记录这一转换。学生仍看到实质证据契约，不只是输出格式。不能将生成阶段使用提示的表现称为学生在相同短提示下已经具备的能力。

## 恢复监督为什么另池

“明确不确定的候选 → 有据消除歧义”与“确定性错误断言 → 后来纠正”具有不同监督风险。后者如果整段计算正向 loss，会同时教会错误断言。

设计上可以保留真实错误前缀作为上下文，只监督合格的后续修正，并记录 recovery_from_step、分支、原始反馈和监督跨度。当前恢复池为空，尚未完成 suffix mask 的实例验证；`recovery_like` 分流不是这一训练机制的实现证明。

## 三种 mask 不能混淆

|机制|控制什么|不能推出什么|
|---|---|---|
|SFT label/loss mask|哪些目标 token 计算监督损失|被 mask 的错误前缀从上下文消失|
|attention/access mask|哪些位置能够读取哪些历史状态|仅改 label 就完成此机制|
|RL token mask / advantage weight|策略输出的梯度位置与权重|rollout 时模型不再看到旧文本|

正确 caption 可以合法传递视觉信息。不能仅因最终答案依赖早先文字，就认定模型没有使用图像。

## 真正训练前需要验证

在明确训练配置后，检查用户/工具/助手边界、每个实际监督跨度、图像占位与顺序、截断；用相应类型真实样本检查 clean 与恢复两种情况。当前 `LF_CHECK` 只是标记数、关键字、图像数和长度检查，未穷尽这些要求。

还需要考虑学生 processor 的呈现尺度：教师读清不意味着学生输入一定读清。是否增加学生小探针应由具体缺口决定，本次没有运行。

## RL 的建议顺序

先建立 correctness-only 的任务闭环基线，再判断是否存在“终答分提高而关键事实/绑定错误未下降”的问题。只有受控证据诊断在目标任务上足够稳定，才考虑引入一种额外的证据或更新奖励。

不以 HOLD/REVISE 关键词次数、caption 长度、crop 数或 raw attention 直接定义成功。否则可能训练出格式表演和无意义重看。后续若做图像干预，应同时考虑原图与多个 crop 中的证据副本，避免只遮掉一份却声称移除了全部信息。
