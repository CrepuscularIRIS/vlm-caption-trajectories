## 数字口径必须修正

来源：r1@160，两份旧E1 clean/E2日志；哈希见[statistics.json](statistics.json)。

- 每个条件 **552题 × 4次采样 = 2208轨迹**；不是2208个独立题目，也不是每题一个样本。旧docs/31和前次Codex复核漏掉了这一点。
- 运行header的`max_crops=8`；clean实际有5条8裁，E2有22条8裁。`N>=7`可称长轨迹，不能称“撞到7裁上限”。
- clean 96条长轨迹里，66条有其他正确采样；其中27条是“自身错、同题有更短的正确采样”。这不支持仅凭一条长轨迹就认定模型绝对不会该题；但正确的其他采样也可能猜对，并不单独证明视觉能力。同题自然采样不是相同决策点的反事实。
- clean精确重复已执行裁框74次/39条轨迹；不含仅与原图重复的首次整图裁。相同框不自动等于相同处理像素，像素相同也不自动等于重复观察对随机续写无作用。c00则已核验像素文件相同。
- 同UID/sample的clean/E2首轮生成文本完全相同仅1045/2208。不能把全部配对当成固定动作前缀上的回执干预。
- E2 `perturb.ok=True`1969、False234、无首裁5；偏移不总能达到预设低IoU，且方向可能改善定位。
- E2−clean准确率为−1.04百分点；按UID簇bootstrap95%区间约[−2.81,+0.72]百分点，尚未按共享图像家族聚类。不是“准确率保持不降”的证明。
- 宽松`ok`与严格`ok_train_rule`每条件仅5条不一致；是评测边界问题，但不能解释主要失败。

## 对导师公式的定位

导师的 $Q_{answer}(h)-Q_{crop}(h)$ 是在**同一个合法决策状态**比较两种行动的期望回报，训练何时停止/继续的偏好。它不能仅凭自然轨迹长度、caption关键词或最终对错得到；也不保证纠正“裁错地方”“1.38读成1.32”“正确数值映射错选项”。后两类可能需要对不同token/状态边界定向，但目前没有因果证据选择哪一类做主损失。

导师原奖励 $R=Y(1-\lambda N)$ 只处罚成功轨迹的crop；Y=0时任意长度都为0。这不证明失败轨迹永远无法通过策略梯度学会省crop：仍有基线、共享参数和成功概率差异。但它确实无法在同为失败的两条轨迹之间仅凭crop数区分优劣。若题目不可由现有工具获取证据，单纯加停止损失不补足信息；若最终猜对而论据错误，原奖励仍计成功。**是否改目标必须说清楚，不能偷偷把groundedness/拒答偏好加进去。**

上一轮[首裁后可停止性设计](../post_crop_decision_20261023/READOUT.md)仍是有条件候选，不因这些案例自动通过，也不因这些案例自动否决。r1@160本轮数据不能当作r1@40同分布证据。
