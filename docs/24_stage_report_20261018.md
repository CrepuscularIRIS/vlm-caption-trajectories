## 2. 逐句对应：理解、动作、结果

### 2.1 “整体结果是正向的，原始 A 已经可以教会有用的行为，而且支持后续 RL 的提升”

- **理解**：A（V2.2 原始库，4,040 条）作为主线；不再需要证明 A 有用。
- **动作**：之后所有实验都从 A 的 SFT checkpoint 出发，评测沿用双库报告的 552 题（440 题分层验证集 + 112 题 V\*）。
- **背景数字**（双库报告）：A 的 SFT .552 → GRPO .664；B 的 GRPO .638；A−B +2.6 个点，显著。

### 2.2 “GRPO 把主动观测这个搞得有点过头了”

- **理解**：这对应双库报告第 8 节的现象：
  - 直答率从 SFT 的 42.9% 降到 GRPO 后的 0.1%；
  - 平均裁图从 1.01 升到 2.31；
  - SFT 时原本能直答答对的题，在 GRPO 后掉分（.949 → .894）。
- **新补的证据**（10-17 读训练日志）：
  - 每批 192 条采样里最短的回复，前 74 步一直是 35–60 token，也就是直答；
  - 从第 83 步起，最短回复变成约 400 token 以上，也就是每条都至少裁一次。
  - 所以直答是在训练第 74–83 步之间消失的。
- **新补的指标**：重复裁图（与之前某框 IoU > .7）的轨迹占比，原版 GRPO .115，SFT .016。这是“过头”最直接的量化：不只是裁得多，还在重复裁同一个地方。

### 2.3 “B 也不算完全没用……插值是不太必要再继续扩大了，但不算是干扰了梯度”

- **动作**：
  - 插值库 B（v4c）不再扩充；
  - 原计划的 B′（与 A 只差一个变量的插值对照）不做；
  - B 的现有结果保留在双库报告里，作为“插值能教会回到原目标、但不带来准确率”的记录。

### 2.4 “从 a 的 checkpoint 重跑 grpo 就好了”

- **动作**：两轮实验的起点、数据、划分、超参与原版 A 组 GRPO 完全相同：
  - 起点：A 的 SFT checkpoint；
  - 数据：GRPO 题集与原版相同；
  - 采样：每题 16 次、每步 12 题，共 165 步；
  - 随机种子：42。
- 只改奖励（第一轮），或奖励加优势归一的分母（第二轮）。

### 2.5 “check 一下 direct 是不是有点问题，比如原图直接 direct 回答是不是可以正常终止以及打分”

在服务器上核对了上一轮 GRPO 实际用的代码和 A 组训练日志：

| 检查项 | 结果 |
|---|---|
| 代码：第一轮直接给答案能否结束 | 能。第一轮解析为答案即记为正常结束、进入打分；协议检查里没有“必须先裁图”的规则（只有 fallback 要求之前裁过图） |
| 代码：直答答对得几分 | 1 分，与裁图后答对相同 |
| 日志：终止状态 | 165 步共 34,128 条采样：33,902 条以答案正常结束，判无效 151 条（0.4%），超长 75 条 |
| 日志：逐条得分 | 原版日志不记逐条得分，只能由代码确认；新一轮已补记逐条的结束状态、裁图数、对错、得分 |

结论是 direct 本身没有 bug，直答消失是训练动力学造成的。一个推断（未单独验证）：只奖励对错时，多裁一次没有代价，又可能提高答对率。

### 2.6 “不要给 hit fallback 这种字面标签的奖励，也不要因为没有调用工具来扣格式分”

- **核对**：原奖励只看终答：唯一一个 `<answer>`、且字母等于正确答案得 1，其余得 0。没有格式分、标签分、裁图分，也没有过程分。
- **新奖励**：在对错之上乘裁图代价，不加任何其他项。
- **单元测试**：
  - 直答答对 = 1.0；
  - 裁 3 次答对 = 0.97；
  - 答错 = 0；
  - 无效终止 = 0；
  - 多个 `<answer>` = 0。

### 2.7 “另外尝试一个额外的约束：reward = correct * (1.0 - 0.01 * crop_count)”

- **实现**：
  - `crop_count` 取环境实际执行的裁图次数（预算 8，所以最多扣 8%）；
  - 答错仍是 0 分，所以裁图代价只在答对时体现；
  - 新代码放在新目录，原版奖励文件用 md5 核对过、未改动。
- **结果**：原样跑塌缩，改动 GRPO 的归一方式后可用。详见第 3 节。

### 2.8 “最后再用同一个验证集对比一下原版的 grpo”

两组都与原版在同样条件下对比：

- **checkpoint**：取同一步，第 160 步；
- **题目**：同 552 题，每题 4 次采样；
- **采样设置**：温度 0.7，采样种子与原版相同；
- **两种评测条件**：
  - E1：正常作答；
  - E2：把首次裁图换成与目标 IoU < .1 的错框，测纠偏；
- **区间**：按图片聚类的 bootstrap 95% 区间。

### 2.9 “主要目标还是减少无效的截图，但是也同时保证答题以及 recover 的能力”

我们把这句话拆成三组指标，并在第二轮开跑前写下了判定标准（第 3.3 节）：

| 目标 | 指标 |
|---|---|
| 减少无效截图 | 直答率；平均裁图；重复裁图（IoU > .7）占比；token |
| 保证答题 | 总体与分层准确率；SFT 时直答答对的 59 题的准确率 |
| 保证 recover | E2 中换错框后再裁、再裁后回到原目标、没再裁就答错、扰动造成的净掉分 |

## 3. 我们重新做了什么设计

### 3.1 第一轮：导师公式原样（10-17，已停）

奖励改为 `correct * (1.0 - 0.01 * crop_count)`，其余全部不变。

**训练中的变化**（每 8 步平均）：

- 直答率 42.9% → 96.5%，平均裁图 0.92 → 0.05；
- 第 40 步验证准确率 .484，低于起点 .502（原版同步 .566），第 56 步按事先写好的条件停止；
- 同一批采样里，裁过图的一直比直答的准，例如第 35 步 .90 对 .41。

**E1（第 40 步）**：

| | A SFT | 原版 GRPO | 第一轮 |
|---|---|---|---|
| 总体准确率 | .552 | **.664** | .511 |
| 直答率 | 42.9% | 0.1% | **94.9%** |
| 平均裁图 | 1.01 | 2.31 | 0.08 |
| 平均 token | 161 | 276 | 69 |

SFT 时直答答对的 59 题保持 .941，说明“该直答的直答”生效了。但其他需要裁图的题，几乎每层都低于 SFT 起点。E2 无法施加，因为 95% 的采样直接作答，没有首次裁图可以替换。

**原因：系数被 GRPO 的组内标准差约掉了。**

GRPO 的优势是 `(r - 组内均值) / 组内标准差`。一道题 16 个采样全答对、只是裁图次数 k 不同时，r = 1 − c·k，优势化简为：

```
A = -(k - 平均k) / k的标准差
```

c 完全消失。后果有三：

1. 不论 c 取 0.01 还是 0.001，全对组里“少裁一次”的推力，都和“答对对答错”一样强。
2. 有对有错的组里，裁图代价又小到可以忽略。
3. 推力只来自全对组，再通过共享参数扩散到需要裁图的题上。

**单纯调小系数无效**；第 17–24 步训练准确率短暂到过 .622，那是训练途中经过的位置，不是某个系数对应的稳态。

文献里有同样的报告：

- Arora & Zanette（arXiv 2502.04463）第 5.4.1 节：长度惩罚在组内标准差归一下与系数无关，会让准确率骤降；
- Dr. GRPO（arXiv 2503.20783）：标准差小的题（全对或全错）会被加上大权重。

### 3.2 第二轮：奖励不变，组内标准差设下限（10-17 → 10-18）

**改动只有一处**：

- 奖励仍是导师的 `correct * (1.0 - λ * crop_count)`；
- GRPO 优势的分母从“组内标准差”改为 `max(组内标准差, 0.25)`。

改后各类组的优势：

| 组 | 优势 | 含义 |
|---|---|---|
| 全对 | `-4λ · (k - 平均k)` | λ 重新有意义：λ = 0.05 时每多裁一次约 −0.2（第一轮是 −1 到 −3.75） |
| 有对有错 | 与原版基本相同 | 二值奖励下 16 个样本只要有一个不同，标准差 ≥ 0.25 |
| 全错 | 0 | 不在难题上压制裁图 |

- 0.25 取的是二值对错奖励下非零标准差的最小值，即 16 个样本 15 对 1 错时的标准差。
- λ = 0 时与原版 GRPO 相同。
- 直观含义：一次裁图要换来大约 λ 的准确率提升，才“划算”。
- 两组并行：λ = 0.025 和 λ = 0.05，各用 2 张卡，约 7–9 小时。

**为什么不选其他写法：**

| 写法 | 出处 | 不选的原因 |
|---|---|---|
| 不除标准差（RLOO / Dr. GRPO） | Arora & Zanette；Dr. GRPO | 对错项的尺度也会变，需再跑一组“只看对错”的对照；玩具模拟中纠偏率降到 .59 |
| 对错项归一，裁图项另加 `-λ(k - 平均k)` | CodeDance（arXiv 2512.17312） | 全错组也会压裁图，难题上探索减少；约 30 行新代码 |
| 只罚超过组内答对样本最少裁图数的部分 | OTC（arXiv 2504.14870）、ShorterBetter（arXiv 2504.21370） | 优势已减去组内平均，再加基准增益有限 |
| 只在组内有人直答答对时才罚 | AGAR（arXiv 2505.15436）、ALP（arXiv 2506.05256） | 方向一致，但需按组判断；下限方案在全对组以外自动不起作用，更简单 |

**玩具模拟**（只作方向性证据）：

- 题型三类：直答就够、需要裁图、首次常裁偏要再裁，比例 .5 / .35 / .15；
- 165 步，8 个种子。

结果：

- 第一轮的公式在模拟里同样塌到 90% 直答，和实测一致；
- 下限方案保住了需要裁图的题（.79–.80 对原版 .83）；
- 下限方案下，模拟的直答率也只有约 .02。这一点事后看，已经预示了直答回不来（见第 5.2 节）。

### 3.3 事先写下的判定标准（开跑前）

- **塌缩，立即停**：
  - 任一步直答率 > 60%，或平均裁图 < 0.3，或第 40 步验证 < .53。
- **最终成功（第 160 步）**，四条同时满足：
  - E1 总体准确率 ≥ 原版 − 1 个点；
  - SFT 时直答答对的 59 题 ≥ .93；
  - E2 纠偏 ≥ 原版 − 2 个点；
  - token 和重复裁图减少。

### 3.4 评测与记录上补的设计

- **重复裁图**：新增指标，与之前某框 IoU > .7 的裁图。
- **SFT 时直答答对的 59 题**：SFT 的 4 次采样里至少 3 次直接作答且答对，用来检查“该直答的题”。
- **E2 配对增量**：同一采样“换错框”对比“不换”多裁的比例。原来的“再裁率”受天花板影响，见第 5.4 节。
- **逐条训练记录**：每条采样的结束状态、裁图数、对错和得分都写入日志，事后可以重算每组的优势。

## 5. 目前遇到的困难

### 5.1 导师的公式不能在 GRPO 里原样使用

- **现象**：第一轮塌到 95% 直答，准确率跌破 SFT 起点。
- **原因**：见第 3.1 节，全对组里系数被组内标准差约掉，“0.01”这个量级在 GRPO 里没有意义。
- **现在的处理**：奖励公式保持导师的形式，改 GRPO 的分母（第二轮）。
- **代价**：这已经不是“只改奖励”。若导师更希望保持 GRPO 原样，需要换别的写法，见第 3.2 节的表。

### 5.2 直答找不回来

- **现象**：直答率只有 3–4%。SFT 时能直答答对的 59 题，第二轮只有 13–16% 的采样直答，准确率 .86–.88，还低于原版 .894。
- **原因**（用逐条训练记录重算了每组优势）：
  - 在有对有错的组里，直答采样比裁图采样更容易答错，所以直答在这些组拿到的优势之和是负的（λ = 0.05：−251）；
  - 这个负值超过了全对组给直答的正推力（+112）；
  - 全对组的推力是“减去组内平均”后的，主要把“裁 2 次”推成“裁 1 次”，很少推成“不裁”。
- **含义**：只要直答在混合组里更容易错，任何“答对 × 裁图代价”形式的奖励都很难把直答找回来。这不是调 λ 能解决的。
- **可能的方向**（未做，需讨论）：只在“首轮已能读出答案”的情况下比较直答与裁图，或者按题区分是否需要裁图。

### 5.3 准确率差 1.5–1.7 个点，分不清是噪声还是代价

- **现象**：两组都低于原版 1.5–1.7 个点，区间包含 0。
- **已排除的一种解释**：“代价删掉了需要的裁图”。按“裁图减少最多 / 中间 / 最少”把题分成三份，掉分是 −1.4 / −1.4 / −2.5 个点，并不集中在裁图减少最多的题上；裁图减少量与掉分的相关系数 −0.015。
- **未排除**：单次训练的波动。每组只跑了一个种子，需要第二个种子才能分开。

### 5.4 “纠偏”的原指标被原版的多裁习惯带偏

- **现象**：E2 的“换错框后再裁”比例，原版 .987，下限组 .953–.966，看起来变差了。
- **原因**：原版本来就在 48% 的采样里裁两次以上（λ = 0.05 只有 20%）。所以原版不论框对不对都会再裁，这个比率接近天花板。
- **处理**：改用配对增量，即同一采样换错框比不换多裁的比例。按这个指标，下限组对错框的反应更大（.69–.78 对 .53）。
- **真正变差的一项**：“没再裁就答错”从 .005 升到 .016–.022，回到了 SFT 的水平。少裁之后，偶尔会在错框上直接作答。

### 5.5 第二轮并不严格是“只差一个变量”

- **现象**：加了裁图代价后，答对样本的得分不再只是 0 或 1。约 20% 的有对有错组，标准差也低于 0.25、被下限截住。这些组多是只有一两个采样答对、而且裁得多的难题。
- **影响**：这些组里答对样本的正信号被削弱。H 层准确率没掉（.256 / .269 对 .262），影响看起来不大，但不能说与原版只差 λ。

### 5.6 训练中的验证曲线不能当独立证据

训练时用的验证集，与 E1 的 440 道分层验证题是同一个文件。训练曲线只用来做塌缩判断；结论都以第 160 步的 E1 / E2 为准。

### 5.7 算力与协调

- 4 张卡与另一个项目共用，第二轮两组各 2 卡、约 7–9 小时，需要先协调空卡。
- 每轮评测（2 组 × E1 + E2）另需约 40 分钟。
- 一个 FSDP checkpoint 约 52 GB，两组同时跑要预留磁盘。

## 6. 下一步与需要导师确认的问题

**建议的下一步**（尚未启动）：

1. **加一个种子重跑**：原版与 λ = 0.05 各一组，4 卡约 7–9 小时，用来确定 1.5 个点是不是噪声。

**需要导师确认：**

1. **直答是否一定要找回来？**
   - 如果“减少无效裁图”指的是每题少裁几次，第二轮已基本达到；
   - 如果还要求“能直接答的题不裁”，需要另一种设计（第 5.2 节），单靠裁图代价做不到。
2. **能否接受改 GRPO 的分母？** 第二轮保留了导师的奖励公式，但把优势分母设了下限。若更希望 GRPO 原样，可以改为不除标准差（RLOO / Dr. GRPO 式），但要多跑一组对照。
3. **“recover”具体看哪一项？** 换错框后的净掉分没有变差，但“没再裁就答错”回到了 SFT 水平。哪一项更重要，会影响 λ 的选择。
4. **1.5 个点以内的准确率差是否可以接受？** 用来换裁图减半、token 少三分之一。
