## 4. 为什么 λ=.01 不起作用（训练账本，0 GPU）

按导师 10-18 的要求把 rollout 分成全对 / 全错 / 有对有错三组统计（[logs/stageA](../logs/stageA/README.md)）：

1. 更新几乎全部来自有对有错组，λ=.01 的代价只占其中 2–5% 的信号。
2. 方向是对的：同一道题里多裁的样本本来就更容易错，所以 λ=0 也在轻微推向少裁。**问题在力度，不在方向。**
3. 约一半的题组里，答对的样本同时有"裁 1 次"和"裁 ≥2 次"，少裁有样本可比。
4. 同一 run 的相邻检查点之间，每题裁图能差 1 次以上（r1：1.89 / 1.99 / 3.49 / 2.08）。只用一个检查点比较，0.3–0.5 次的差异分不清是方法还是波动。
5. 严格势函数在轨迹级 RLOO 下完全抵消（代数检查）。要用导师说的势能方程，就得按轮计算回报，或者接受它改变目标。

## 6. 文献卡片怎么用

[vlm-caption-corpus](https://github.com/CrepuscularIRIS/vlm-caption-corpus) 的 92 张机制卡作参考，不作新的框架：

- PC-F1-01 / F1-03：代价放在标量奖励里，会被 std 约掉，或被对错差淹没。和第 4 节一致；RLOO 没有除 std，所以剩下的是力度问题。
- PC-F5-03：按题通过率收缩轮数预算。如果单靠 λ 掉分，可以作为备选。
- PC-F2-20：势函数的代数（第 4 节第 5 点）。
- PC-F5-09 / F5-10：多检查点、多种子，逐题统计"对→错"回归。每组实验同时报告训练 token、更新次数、rollout 开销（导师 10-18 要求）。

卡片路线里"先保住直答"那一阶段不适用于本项目：导师已说明直答少是正常的。
