## 2. cc 增强的究竟是什么

原路线是任务内 `cc` 包装调用官方 Claude CLI；新增路线是用户配置的 Claude Code `cc` 包装，经既有代理链访问 Claude Sonnet，使用独立回执目录与预算键。**这是审核通道的补充，不是增加一个独立模型家族，也不是把 Sonnet 换成 Kimi。**

273 份生产回执都报告 `claude-sonnet-5-5` 与初始化阶段的 `claude-sonnet-5-5[1m]`。CLI 的配置槽名称不是模型身份依据。此次重新解析已有 stdout，核对退出状态、返回模型、文本结果、所有指定图片被 Read 成功打开、无额外工具和越界读取。**273/273 有效且与原回执关键字段一致**；141 条补审轨迹关联的 **479 个**结构/盲读回执关系均存在且 valid。[脱敏回执索引](../data/cc_receipts_20261004.json)

**“无超时”只适用于稳定后的生产目录。** 早期归档 smoke 另有两次 300 秒超时；预算账共 275 次 dispatch，与 273 次有效生产调用、2 次归档失败对得上。源码说明包装器默认 effort 环境变量会覆盖命令行设置；稳定版本显式设为 medium。失败历史保留，不将其从可靠性或成本记录中抹去。

审核仍是 Sonnet 结构/绑定与关键事实、Grok 前缀盲读，以及隔离的文字比较和分歧复读。不能因改走 cc 就称为三家完整评委投票，也不能从 76/141 推断审核精度提高：新增题主要是学科和视觉谜题，尚无人工真值。新增通道已证明可运行、可继续完成审核；语义质量仍需人工校准。

[cc 适配器与审核入口阅读快照](../code/reference/cc_update_20261004/README.md) 保留实际验证逻辑，去掉本地路径和账户说明；没有公开原始 CLI 隐藏推理或凭证。

## 4. 被拒的题是否定向重做

**先完成人工校准，再挑有教材价值的题有限重做。** “拒绝”是某条轨迹被审核否决，不等于题目无价值或所有审核判断均正确。原轨迹多数已经过答案门，重做的目标是得到更好的证据过程，不是刷到同一个正确字母。

对最终 916 条拒绝记录，按明确规则初步分流：

|建议优先动作|数量|含义与边界|
|---|---:|---|
|先审已有其他模型路径|531|至少一条已提交且金标评分正确的替代轨迹；未完成替代路径的过程验收，不能直接入池|
|先查上下文/可读性|30|拒绝原因仅为关键事实或终答盲读不足；先区分视图包缺失与真实证据不足|
|进一步筛选有限定向重做|355|没有已答对的替代路径，且不属于上一类；仅为待筛候选，不是已批准执行的生成队列|

另外 **275 条争议、12 条审核格式问题**先裁定证据或修审核输出，不直接当成生成失败。[逐项建议与替代结果来源](../data/rejection_triage_20261004.json)

531 条中已有 GLM 答对路径的为 469、Grok 116、Sol 31、K3 5、K2.8 1，各列有重叠，不能相加当题数。这里不要求替代者必须独立家族；若以后要标记生成共识，还须额外满足家族、对象和事实一致条件。GLM 仍在运行，完成后应刷新已有替代路径，再决定哪些仍有必要重生成。

355 个待筛候选为自然图 238、计数 59、学科 20、视觉谜题 20、图表 16、文字 2。优先选择有可读证据、明确区分线索、能补绑定/主动补证/保持能力的独立图组。题意歧义、金标待核、图像不可读者先隔离；混有审核 schema 问题的先核清拒绝依据。人工抽检若发现系统性误拒，应先修审核器并公平重判相关层，不靠换生成器掩盖。

建议每题冻结少量尝试上限，保留原轨迹和拒绝原因；可调整教师档位与非泄漏的通用引导，不给生成器 gold、目标对象或预定错误步骤。新路径按同样门槛审核，不刷到通过；有错误前缀的恢复教材另行处理。Sol/K3 是已有方案中的候选教师，本次没有调用。
