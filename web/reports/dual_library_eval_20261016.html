原始库 A 与插值库 B：评估与轨迹审查

A 原始轨迹 V2.2（协议 v5.1）   B 插值轨迹 v4c（协议 v6）  ·  两库同一批 3,983 题，各做一次 LoRA SFT + 165 步 GRPO
  1. A 已经够用。A 做 SFT + GRPO 后准确率最高（.664），而且 A 自己学会了“看错后重新找”：被换成错误视图后，98.7% 会重新裁图，70% 回到原目标区域。A 原库里明确的纠偏示范只有约 3%，SFT 后已有 73% 的错框后用 fallback，GRPO 推到 94%。我们的判断是 SFT 种下模式，GRPO 放大。
  2. B 的插值是人为偏移，不是“自己发现错误再改正”。构造器把生成模型自己要的裁图框换成偏框，模型在真实的偏框画面上写出反应（多为 miss → 移动），只训练这个反应。B 确实学会了这种反应，但它没有转化成准确率：RL 后 B 比 A 低 2.6 个点。
  3. 发现一个小裁图问题。两个模型 SFT 后首次裁图的中位面积都只有原图的 2–3%。A 经过 RL 后放大到 10%；B 仍只有 3.8%，裁偏以后每步只平移一点，B_sft 有 7.2% 的采样把 8 次裁图用完。
  4. 两组 RL 后都不再直答（直答率 43% / 41% → 0.1%），这一点和“能直答就直答”的要求相反，下一轮需要处理。

1实验与准确率

2B 的插值是怎么做的

做法是强制偏移。用强模型生成轨迹时，在它自己提出裁图请求的那一轮，文字保持原样，只把实际执行的框换成一个错的框。偏框真的被执行，下一轮模型看到的是偏框里的真实画面，再由它自己写出反应。

第 k 轮 · 生成模型示意：“我要看目标所在的区域”写出裁图请求，框 = 目标区域
构造器替换 · 不训练实际执行偏框五类偏法：平移、截断、过紧、过宽、远处。这一轮整轮不计 loss，只留在历史里
第 k+1 轮 · 生成模型 · 训练示意：“SEE: miss — 这一框里没有目标”看着真实的错误画面，写出 miss / partial 并平移或放大

构造参数：每题计划 0–4 次偏框，92% 的题至少 1 次；第一次裁图被偏的占 55%；连续两次偏框占 35%。另外，给生成模型的条件里，85% 的题加了“逐条核实每个事实”的要求。

3A 为什么也会纠偏：SFT 种下，GRPO 放大

A 的 4,040 条原始轨迹审查过答案正确，没有专门构造纠偏，协议里也没有 miss 这个词，但里面有可学的模式：

GRPO 只看最终答案对错。它没有教新动作，而是把 SFT 里少量出现的“这一框没用、换个地方”变成默认动作。这是假设，竞争解释有两个：

  • 基座模型加上协议提示本身就会这样做，与 SFT 示范无关。区分：用 v5.1 协议对未经 SFT 的基座模型跑同一扰动测试。
  • 起作用的是 18% 的“换区域”轨迹，不是 3% 的纠偏轨迹。区分：从 A 库删掉这 110–131 条后重训，再测扰动表现。

例子：

A SFT+GRPO · vstar_188 · 被换成偏框之后的第二轮（这一条最后仍答错，这里只看它是否发现裁偏）Step 2 | fallback — This crop shows white umbrellas but no yellow or pink umbrellas [observation_1]. Shift right toward the beach and umbrella cluster.

A 的代价是会绕圈：14% 的裁图和之前某一框几乎重合，比如在 [0,0,.5,.5] 和 [0,0,.6,.6] 之间来回。即使这样，A 用 4 次以上裁图时的准确率（.526）仍高于 B（.399）。

B 的另一个问题出在 GRPO 之后：最后一轮的判断 99.5% 都是 hit，而说 hit 时的准确率只有 .639，和总体一样，这个自检标签已经不提供信息。B_sft 时还有区分（hit .621，miss .091）。

5共同问题：GRPO 后不再直答

两组 GRPO 后几乎每题都先裁图（直答率 0.1%）。在 SFT 原本直答且答对（4 次至少 3 次）的题上，GRPO 后准确率反而下降：A 从 .949 降到 .894，B 从 .953 降到 .859，生成 token 约多 3 倍。典型情况是模型已经从原图读对，裁图“确认”时又改错：

mme_7685 · Rent Trend 图中 2020 年 Qtr2 的数值（正确答案 2.1）A SFT（直答，对）：the column labeled Qtr2 (year 2020) shows the value 2.1 → A A GRPO（裁图后，错）：In [observation_1] … “Qtr2” with value 2.2 … So the requested 2020-Qtr2 data is 2.2. → B

6结论的边界

  • A 和 B 不只差“有没有插值”：还差生成模型、协议（v5.1 对 v6）、“逐条核实”要求、偏框这四样。所以只能说这一版插值库没有带来准确率提升，不能说“纠偏示范没用”。
  • 每组只训了一次 SFT、一次 GRPO、一个种子。
  • “SFT 种下、GRPO 放大”目前只有行为随训练阶段一致增强这一证据，第 3 节的两个区分实验还没做。
  • 扰动只换第一次裁图；单个样本的得失有很大采样噪声（扰动后反而答对的样本有 132–175 个），只看净差。

7下一步，请导师定方向

  1. 以 A 为主线继续，在 GRPO 奖励里加小的裁图代价，把直答找回来，同时看小框裁偏后的恢复。
  2. 验证“SFT 种下、GRPO 放大”：基座模型扰动测试，或删掉 A 库纠偏轨迹后重训。
  3. 如果仍要验证插值，做只差一个变量的对照：用 A 的协议和生成模型，只插入偏框和真实反应，去掉“逐条核实”要求，降低第一步被偏的比例。
  4. 人工看图核对 50 条“说 hit 但答错”的轨迹，区分“框里有答案但读错”和“框里根本没有答案”。
